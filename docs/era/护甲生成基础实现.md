## 调用与保存边界

`IEraArmorGenerator.Generate(EraArmorGrade)` 是后端内部入口，沿用现有 `IScope` 自动注册；未增加公开生成 API。返回结果包含品阶、`GenerationRuleVersion` 和六维最终整数，不创建装备 ID、归属、地面记录或发放回执。

未来奖励流程必须先检查业务事件及历史回执，只在首次正式生成时调用，并将结果与装备、地面记录、分享资格和发放回执一起提交。重试、查询、拾取及再次丢出都读取保存结果，不能重新调用生成器。当前尚未实现这段持久化与防重流程，生成结果本身不代表正式资产。

规则版本当前为 `1`，表示本版生成算法，不是配置发布版本、资产并发版本或缓存版本。本批未修改任何现有缓存版本。

## 基础契约

新增枚举显式赋值，从 `1` 开始；`0` 未定义，未知品阶会被生成器拒绝。客户端现有本地枚举从 `0` 开始，接入时必须按语义映射，不能直接强制转换。

| 契约 | 协议值 |
| --- | --- |
| `EraArmorSlot` | Head=1、Body=2、Hands=3、Backpack=4、Legs=5、Feet=6 |
| `EraArmorGrade` | Worn=1、Common=2、Reliable=3、Unusual=4、Unique=5 |
| `EraArmorAttribute` | Strength=1、Survival=2、Mobility=3、Focus=4、Efficiency=5、Resistance=6 |

`Backpack` 指六类护甲中的背包装备部位。后续已补充的物品背包分区、位置、归属与查询版本契约见 [装备存储与只读接口](装备存储与只读接口.md)，写操作契约仍待接入。

`EraArmorAttributesDto` 使用上述六维的具名整数属性，只表达单件装备原值，不携带生成时的主次排序或整数基准。历史实例的展示与使用不依赖重新推断生成过程。六维生效、BUFF 合并和动态冷却由游戏运行时负责。

## 生成方式

按五档预算计算六个分配位置的整数基准，用整数余量排序补点，同余量允许随机处理。随后在有界整数空间中选出满足预算、非负、±3 及主次层级的联合分配，最后独立随机排列到六维。

合法分配使用蓄水池抽样，不保存全部候选，也不依赖无限重试。生成入口不接收护甲槽位，不设置部位专属主属性或偏向。
