# 敌人配置管理

更新：2026-11-03。后端与 Web 源码已接入，真实 API／数据库联调尚未执行，客户端暂不接入。

## 保存、发布与兼容

敌人定义复用 `era_skill_draft_record`，新增类别 `Enemy=3`，使用既有工作区锁、唯一索引、工作单元、版本冲突、草稿删除与统一原子发布；无需新建数据表或执行新迁移。保存不会立即生效。

管理端配置导出／发布／历史增加可选 `enemies` 集合，结构版本仍为 3。省略或 `null` 的旧导入保留现有敌人；完整替换时显式 `enemies: []` 标记删除全部敌人。历史恢复代表还原完整历史，旧历史未包含敌人时会清空敌人草稿，仍需预检发布。历史原文和已有内容哈希不改写。

游戏端配置接口在返回前去除 `Enemies`，`JsonIgnore(WhenWritingNull)` 确保响应中不出现该字段，维持现有客户端严格 JSON 契约。未新增客户端目录读取入口、导航寻路或敌人运行逻辑，未修改客户端 schema、缓存版本或文件。

## 管理接口

根路径 `/api/era/admin`，复用认证与 `EraAdminController` 接口权限，管理接口不要求游戏会话 Header。普通管理员需要注册 `/admin/era/enemies` 菜单资源并授予对应接口及所用候选读取权限；超级管理员沿用现有机制。

| 方法与路径 | 用途 |
| --- | --- |
| `GET enemies?skip=0&take=20&search=名称或Key&includeDeleted=false` | 分页搜索；take 1～100，search 最多 256 字符 |
| `GET enemies/{id}` | 单条草稿详情 |
| `POST enemies/{id}` | 完整保存，body 为 `{ expectedVersion, definition }` |
| `POST enemies/{id}/delete` | 标记删除，body 为 `{ expectedVersion }` |
| `POST enemies/{id}/restore` | 恢复草稿，body 为 `{ expectedVersion }` |
| `GET configuration/references?kind=3&id=敌人Key&skip=0&take=50` | 敌人反向引用；当前无引用敌人的后台配置，返回空集合 |

统一复用 `configuration` 下的 status、export、validate、preview、import、publish 和 history 接口。预检路径使用 `Enemies/{id}`；技能／效果的反向引用包含敌人引用位置。种族、阵营、技能或效果被删改后，仍被敌人引用的配置不能发布；草稿删除不会自动清理敌人引用。

响应沿用 `{ code, errorCode, message, data }`。单项 data 为 `{ id, version, draftRevision, isDeleted, wasPublished, definition }`；分页 data 为 `{ draftRevision, total, items }`。版本均为 JSON Int64 整数，Web 保持精确字符串直到序列化，代理保留请求／响应原始 JSON。

创建 `expectedVersion=0`；更新使用已读版本，重复 Key／过期版本返回 `era.draft_version_conflict`。Id 使用稳定业务 Key，创建后不通过更新改名，复制时填写新 Key。定义 Id 必须与路由相同。Key 最多 128 字符、非空、首尾无空格；名称必填最多 256 字符，说明最多 2048 字符。表现 Key 只校验格式，不检查客户端资源文件存在性。

## EnemyDefinition

| 字段 | 类型与约束 |
| --- | --- |
| `id`、`name`、`description` | 敌人 Key、名称、备注 |
| `presentationKey` | 必填表现 Key，关联客户端资源数据集，可被多敌人共用 |
| `speciesId`、`factionId` | 必填，引用当前草稿种族／阵营目录 |
| `maximumHealth` | 有限数值，1～1,000,000,000 |
| `maximumProtection` | 有限数值，0～1,000,000,000 |
| `walkSpeed`、`runSpeed` | 0～1000 m/s，不强制两者大小关系 |
| `ai` | 下述行为参数 |
| `normalAttack` | 下述内嵌普通攻击参数 |
| `skills` | 技能引用列表，最多 256 项，同技能不可重复 |
| `initialBuffs` | 效果 Key 列表，最多 256 项，不可重复 |
| `recovery` | 下述脱战恢复参数 |

不含六维属性、区域、出生点、生成／刷新数量、地图路线、运行时生命或 AI 状态。敌人及嵌套对象拒绝未知字段。单条定义最多 256 KiB；沿用目录发布 256 KiB 与草稿 1 MiB 预算，每类草稿记录最多 10000 项（含删除标记）。

### AI

| 字段 | 含义与范围 |
| --- | --- |
| `behavior` | 0 驻守、1 巡逻、2 自由漫游 |
| `aggression` | 0 主动攻击、1 仅反击 |
| `perceptionDistance` | 感知距离，0～1,000,000 m；0 为无距离感知 |
| `fieldOfView` | 视野角，0～360°；0 不覆盖视野角，360 为全向 |
| `perceptionIntervalSeconds` | 检测间隔，0.001～86400 s |
| `targetMemorySeconds` | 失去感知后的目标记忆，0～86400 s；0 不保留 |
| `maximumChaseSeconds` | 单次追击时限，0.001～86400 s |
| `stopDistance` | 接近目标时停止移动的距离，0～1,000,000 m |
| `stuckTimeoutSeconds` | 连续受阻处理阈值，0.001～86400 s |
| `idleMinimumSeconds`、`idleMaximumSeconds` | 漫游目的地之间停留范围，0～86400 s，最大不得小于最小 |

这是参数存储语义；地图负责提供驻守点／路线，自由漫游不要求区域引用。寻路失败、路线缺失、追击结束后的行为与联机权威由客户端后续实现，本轮不新增后台地图规则。

### 攻击与 BUFF

`normalAttack` 包含 `enabled`、`damage`、`distance`、`windupSeconds`、`backswingSeconds`、`cooldownSeconds`。伤害 0～1,000,000,000，距离 0～1,000,000 m，各时间 0～86400 s。关闭时保留并校验参数，不要求攻击方案 Key。数值存储不代表本轮已实现攻击结算；命中、动画与资源挂点由后续客户端接入约定。

`skills` 每项为 `{ skillId, slot, priority }`。slot 沿用技能现有 0 特殊／1 主要／2 次要／3 战术方案，引用的技能必须存在该方案；priority 为 0～Int32.MaxValue，大者优先，同级按列表顺序。冷却和效果由技能定义，不在敌人中复制。具体释放资格与目标处理由后续 AI 实现。

`initialBuffs` 每项为现有效果 Key。仅允许周期效果（kind=2），各项初始化时给予一次，不单独配置层数；后续叠加、寿命和刷新遵循原效果定义。禁止六维属性修正（stat 0～2、7～9），允许直接数值属性及周期伤害／治疗／防护恢复。单项保存校验当前引用；统一预检再次校验，防止候选随后被删除或改成不支持的类型。

### 恢复

`recovery` 包含 `healthEnabled`、`delaySeconds`、`healthPerSecond`、`protectionPerSecond`。延迟 0～86400 s，恢复率 0～1,000,000,000 /s。约定在脱战并满足最近受伤后的延迟后恢复，生命受开关控制，防护独立，速率 0 表示不恢复；该运行规则本轮仅配置，不执行实例计时。
