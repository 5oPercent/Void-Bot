## 管理接口

根路径 `/api/era/admin`，复用认证与 `EraAdminController` 接口权限，管理接口不要求游戏会话 Header。普通管理员需要注册 `/admin/era/enemies` 菜单资源并授予对应接口及所用候选读取权限；超级管理员沿用现有机制。

| 方法与路径 | 用途 |
| --- | --- |
| `GET enemies?skip=0&take=20&search=名称或Key&includeDeleted=false` | 分页搜索；take 1～100，search 最多 256 字符 |
| `GET enemies/{id}` | 单条当前详情 |
| `POST enemies/{id}` | 完整保存，body 为 `{ expectedVersion, definition }` |
| `POST enemies/{id}/delete` | 标记删除，body 为 `{ expectedVersion }` |
| `GET configuration/references?kind=3&id=敌人Key&skip=0&take=50` | 敌人反向引用；当前无引用敌人的后台配置，返回空集合 |

`configuration/export` 从各表读取当前目录，`configuration/references` 查询当前反向引用。保存和删除立即校验现有引用，不再提供发布、历史恢复或版本缓存接口。

响应沿用 `{ code, errorCode, message, data }`。单项 data 为 `{ id, version, revision, definition }`；分页 data 为 `{ revision, total, items }`。`version` 和 `revision` 只用于编辑并发与一致性读取，使用 JSON Int64；Web 保持精确字符串直到序列化。

创建 `expectedVersion=0`；更新使用已读版本，重复 Key／过期版本返回 `era.data_version_conflict`。Id 使用稳定业务 Key，创建后不通过更新改名，复制时填写新 Key。定义 Id 必须与路由相同。Key 最多 128 字符、非空、首尾无空格；名称必填最多 256 字符，说明最多 2048 字符。表现 Key 可保存为空字符串（未传时 DTO 默认空字符串），不接受 null 或纯空格；使用时按 `presentationKey === "" ? id : presentationKey` 解析。保存和读取保留空值，不自动回填 Id；只校验非空 Key 的格式，不检查客户端资源文件存在性。客户端通过本地表现目录解析资源。

## EnemyDefinition

| 字段 | 类型与约束 |
| --- | --- |
| `id`、`name`、`description` | 敌人 Key、名称、备注 |
| `tier` | 稳定数字枚举，默认 0 普通 Minor；1 精英 Elite、2 精锐 Major、3 首领 Ultra、4 头目 Boss，拒绝其他值 |
| `presentationKey` | 可留空字符串，默认按敌人 `id` 查找表现资源；填写时最多 128 字符、首尾不含空格，可被多敌人共用 |
| `speciesId`、`factionId` | 必填，引用当前种族／阵营目录 |
| `baseHealth` | 基础生命，1～1,000,000,000，默认 100 |
| `baseProtection` | 基础防护，0～1,000,000,000，默认 50 |
| `tierMultipliers` | 本敌人独立的五档生命／防护／伤害倍率表，见下文 |
| `walkSpeed`、`runSpeed` | 0～1000 m/s，不强制两者大小关系 |
| `recoveryDelaySeconds` | 基础数值中的恢复延迟，0～86400 s，默认 5 |
| `healthRecoveryPerSecond`、`protectionRecoveryPerSecond` | 基础数值中的每秒生命／防护恢复量，0～1,000,000,000，默认 0 |
| `ai` | 下述行为参数 |
| `normalAttack` | 下述内嵌普通攻击参数 |
| `skills` | 技能引用列表，最多 256 项，同技能不可重复 |
| `initialBuffs` | 效果 Key 列表，最多 256 项，不可重复 |

不含六维属性、区域、出生点、生成／刷新数量、地图路线、运行时生命或 AI 状态。敌人及嵌套对象拒绝未知字段。单条定义最多 256 KiB；组合目录最多 1 MiB，每类当前记录最多 10000 项。

### 逻辑行为与动作

非战斗行为固定为战斗区域内巡逻，删除 `behavior`、`maximumChaseSeconds`、`idleMinimumSeconds`、`idleMaximumSeconds`。区域边界、路线与攻击名额由地图配置，不存入模板。继续保留 `aggression` 主动攻击／仅反击。

新增视觉／听觉／近距感知、反应区间、目标重评与归一化评分、切换阈值、偏好距离、后撤、转向和掩体／绕侧／进攻／防御／支援偏好。普通攻击开放近战和直射，增加首次等待、误差、散布与动作权重；技能引用增加类型化条件 `decision`，效果与冷却沿用技能定义。

`skills` 仍按 `skillId` 唯一，每项独立维护一个执行实例，`priority` 只用于同分排序。`defense.skillId` 必须引用列表中的自身动作，反向引用与删除保护因此沿用 `Enemies/{id}/Skills` 路径。自身载体只能配自身目标；支援目标不能申请敌对攻击名额。条件为类型化字段，不接受表达式或脚本字符串。

字段、默认值、边界、排序与首次攻击窗口完整见[三端敌人行为字段契约](C:/Users/Feng/Documents/GodotProjects/ERA/docs/敌人行为字段契约.md)。客户端强制区域内完整路径和位移；地图无路线时从导航选择可达点，失败等待重试。

`initialBuffs` 每项为现有效果 Key。仅允许周期效果（kind=2），各项初始化时给予一次，不单独配置层数；后续叠加、寿命和刷新遵循原效果定义。禁止六维属性修正（stat 0～2、7～9），允许直接数值属性及周期伤害／治疗／防护恢复。单项保存校验当前引用；统一预检再次校验，防止候选随后被删除或改成不支持的类型。

### 基础数值与独立等阶倍率

每个敌人保存自己的 `tierMultipliers`，固定 `minor / elite / major / ultra / boss` 五行，每行固定 `health / protection / damage` 三项。默认值仅用于新建，可独立修改任意项；切换当前 `tier` 不重置基础值或任一档倍率，不是全局倍率表。

| 等阶 | 生命倍率 | 防护倍率 | 伤害倍率 | 默认基础值下的生命／防护／伤害 |
| --- | ---: | ---: | ---: | --- |
| 普通 Minor | 1 | 0 | 1 | 100／0／10 |
| 精英 Elite | 5 | 3 | 2 | 500／150／20 |
| 精锐 Major | 10 | 6 | 3 | 1000／300／30 |
| 首领 Ultra | 20 | 10 | 4 | 2000／500／40 |
| 头目 Boss | 100 | 0 | 2 | 10000／0／20 |

- 生命上限 = `ceil(baseHealth × tierMultipliers[当前档].health)`。
- 防护上限 = `ceil(baseProtection × tierMultipliers[当前档].protection)`。
- 普通攻击伤害 = `ceil(normalAttack.baseDamage × tierMultipliers[当前档].damage)`。

倍率是直接乘数；例如 100.1 × 2.5 向上取整后为 251。生命倍率 0.001～10000，防护及伤害倍率 0～10000，均须为有限数值；验证全部五行，包括未选中的档位。0 倍防护／伤害结果为 0，不表示客户端能力启停。基础数值仍保留小数，计算结果统一向上取整；不重复存储最终值。

JSON 字段直接使用 `baseHealth / baseProtection / normalAttack.baseDamage`，不保留旧 `maximumHealth / maximumProtection / normalAttack.damage` 的转换逻辑。表格及行对象拒绝未知字段；显式传倍率表时必须提供完整五行及三列。客户端管理员生成入口读取敌人目录并装配独立实例。

### 等阶与 HUD 对应

`EnemyTier` 使用 `Minor=0 / Elite=1 / Major=2 / Ultra=3 / Boss=4`，前后端保持相同数值。等阶选择本敌人倍率表中对应的一行，生命上限、防护上限和普通攻击伤害分别按基础值乘该行倍率并向上取整；不缩放速度、恢复、AI、掉落或引用技能／BUFF 的效果数值。颜色、图标、旋转、血条宽度与屏幕位置由客户端 HUD 资源维护，不另存后台表现开关。

### 生存、移动与恢复

恢复参数与基础生命、基础防护、行走速度、奔跑速度一起放在 `EnemyDefinition` 顶层，不再保存独立 `recovery` 对象或 `EnemyRecoveryDefinition`。Web 在“强度数值”编辑基础数值与倍率，在“逻辑行为”统一编辑速度、恢复参数及 AI 行为。恢复字段为 `recoveryDelaySeconds`、`healthRecoveryPerSecond`、`protectionRecoveryPerSecond`，范围及默认值见上表。

客户端决定实体是否具备及启用恢复能力，并在满足脱战和最近受伤后的延迟后按参数恢复；后台不提供恢复启停开关。生命和防护的恢复率独立，速率 0 表示该项没有恢复量，不据此决定是否挂载恢复能力；本轮不执行实例计时。

实际业务数据尚未盘点，不能假设不存在旧模板；本轮使用 Script0054 调整敌人 Payload。游戏端通用能力目录仍不携带敌人集合，客户端管理员敌人生成入口单独读取敌人 API。

## 客户端靶子的配置边界

客户端靶子是否具备 AI，由客户端实体的脚本／组件决定。后端不增加 AI 启停字段，也不新增“靶子”类型枚举；现有 AI 参数供具备 AI 的敌人使用，不要求靶子执行这些行为。驻守、仅反击或将移动速度设为 0 均不用于表达“没有 AI”。
