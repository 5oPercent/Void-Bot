# 私人地面奖励与拾取

## 接口

| 方法与路径 | 消息 | 行为 |
| --- | --- | --- |
| POST `/api/era/worlds/{worldInstanceId}/rewards/ground` | SubmitEraGroundRewardCommand | 当前房主按已配置的怪物或宝箱节点生成私人地面奖励 |
| GET `/api/era/worlds/{worldInstanceId}/equipment-drops` | GetEraEquipmentDropsRequest | 查询登录玩家在该世界可领取的私人掉落 |
| POST `/api/era/worlds/{worldInstanceId}/equipment-drops/{dropId}/pickup` | PickupEraEquipmentDropCommand | 本人角色领取私人掉落，返回完整角色装备快照与历史成功回执 |

Controller 复用 ERA 登录、客户端会话及限流策略，只调用 Mediator，并覆盖正文中的路由 ID。GET 不写状态、不刷新世界活动。普通业务错误沿用 BusinessException、VoidBotResponse／EraResponse 及稳定 ErrorCode。

本入口只实现配置为 Ground 的节点，Inventory 节点返回 `era.drop_delivery_unavailable`，不将地面配置自动改成背包；任务、怪物和宝箱按配置选择发放方式的通用规则不变，内部背包能力仍独立提供。此接口不接受任务完成上报，不新增任务系统。

## 事件与权限

房主提交 RequestId、MemberId、AuthorityEpoch、SourceType、SourceDefinitionId、SourceInstanceId、TriggerIndex、RewardNodeId，以及 Placement。Placement 保存 X／Y／Z 世界坐标及 YawRadians，所有数值必须有限；位置由客户端在触发时捕获，后端不验证战斗结果或拾取距离。

领取名单由后端生成：取仍继续参与该世界、活动角色有效、当前 Redis 队伍成员身份与角色一致且租约有效的成员。每位成员独立进行节点概率判定和池内抽取；客户端不能指定品阶、数量、属性、领取名单或分享名单。空奖也保存成功事件和该玩家的空回执。

事件作用域固定为真正 WorldInstanceId，同时保存世界外键。业务唯一身份为世界、SourceType、SourceInstanceId、TriggerIndex、RewardNodeId。SourceDefinitionId 与 Placement 属于必须一致的内容，不用更换定义、房主或代次绕过防重。房主身份和代次只用于重新授权，不进入规范化事件内容；新房主沿用原事件身份可以拿回固定结果。

RequestId 在世界范围内唯一；同 ID 改参数、不同 ID 指向同事件但更改定义或落点，均返回 `era.drop_idempotency_conflict`。不同 ID 同事件同内容只登记别名，不重复抽取。历史成功重试仍需通过当前房主权限校验，不查当前奖励配置，也不恢复装备或地面状态；世界结束后符合历史成员及当前房主权限的重试仍只返回原回执。

新奖励锁顺序为：奖励作用域 → 按固定顺序锁全部候选玩家 → 全部候选角色 → 队伍协调行 → 世界排他锁 → 配置共享锁。在队伍锁内复用现有 Redis 递增栅栏及实时房主校验，要求世界 Ready、活动指针匹配，SQL 房主／代次与实时权限一致。成员在预读后新增时整笔拒绝为 `era.drop_members_changed`，让原请求重试；不在持有世界锁后反向补锁玩家。

配置、名单、属性生成结果、事件、每玩家回执、装备、护甲、地面记录和原分享资格同一事务提交。失败没有已接受事件或半份资产；重试从未成功的事件重新执行。成功接受后固定版本、名单、结果、CreatedAt 和 ShareUntil。

首版信任授权房主报告来源触发，不能证明真实击杀、开箱或一个新来源 ID 是否伪造；来源 ID、触发次数、待提交内容与原始落点仍须由客户端纳入对象同步和迁移恢复。

## 私人可见与拾取

生成后的装备 Location = Ground，OwnerPlayerId、CharacterId、EquippedSlot 为空。地面记录通过 PrivateOwnerPlayerId 表达原始领取资格。房主生成响应只包含世界、事件、版本、时间及各玩家的装备／掉落 ID，不包含队友的完整属性；查询只返回登录玩家的私人条目，后端不先返回全队数据让客户端隐藏。

查询用单条 SQL 固定世界、活动指针、本人成员状态、角色装备版本及私人掉落／装备／护甲。定义缺失或当前目录不可用时返回保存结果及 DefinitionId 降级展示，不重抽，也不阻止旧装备拾取。

拾取提交本人 CharacterId、RequestId、ExpectedEquipmentVersion、ExpectedDropVersion 和 ExpectedItemVersion。后端先锁玩家／角色、检查历史成功回执，再锁队伍与世界，校验世界 Ready、本人继续状态及角色匹配，随后锁掉落与装备。它不要求房主身份或房主代次，正常迁移不会撤销仍有效的私人领取资格。

只允许 PrivateOwnerPlayerId 对应玩家领取。整批背包分区计数沿用每分区 12 件、不含已穿的规则；满包返回 `era.drop_inventory_full`，不修改掉落或建立成功回执。版本不符返回 `era.drop_version_conflict`，未授权或不存在的掉落统一返回 `era.drop_not_found`。

成功时同事务将装备转入本人世界角色背包，设置归属、增加实例版本，将地面记录置为 PickedUp、清空 ActiveEquipmentId 并增加地面版本，角色 EquipmentVersion 加一，保存完整资产快照和拾取元数据。角色普通 Version、原始属性、装备 ID、首次生成时间和分享期限不变。

拾取与装配、卸下共用玩家范围 RequestId 唯一约束，Pickup 操作枚举值为 3。历史拾取回执 IsReplay = true，只返回当时结果；角色后来禁用、世界结束或装备流转不据此恢复资产。旧装配／卸下回执中的新增 Pickup 字段默认为空，格式向后兼容，不提升缓存版本。

## 分享数据与世界结束

首次生成时保存每件装备的当前有效队伍成员名单快照及 CreatedAt + 1 小时的 ShareUntil。分享名单与私人发放名单分别确定：当前队友即使尚未完成 SQL 世界加入，也进入原分享名单，但此时不为其生成私人掉落，也不能查询或领取他人的私人掉落。初始掉落始终私人可见；期限届满不公开、不自动销毁、不更换原始领取人。拾取不刷新分享期限。本批只保存资格，不实现背包主动丢出、公开分享掉落查询或分享拾取。

新奖励、拾取和世界结束都在同一队伍／世界锁内互斥。主动结束、构建失败释放、最后成员离开、异常超时统一经 FinishWorldAsync：先将仍 Available 的地面记录置为 Invalidated、释放 ActiveEquipmentId，并将对应无主 Ground 装备置为 Destroyed，再执行原世界终态转换和活动标记释放，同事务提交。

已拾取装备不会因历史地面记录而销毁；属性、回执及分享记录保留。重复结束仍保持原终态，不清理其他世界。保存失败全部回滚，可安全重试。当前清理使用单次事务，尚未增加分批后台清理。
