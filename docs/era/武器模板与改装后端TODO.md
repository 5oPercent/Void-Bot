- 十一项基础属性来自公共模板，实例不保存基础或最终属性副本，不沿用护甲随机六维生成算法。

- 配置统一复用 `era_equipment_configuration.Version`；不为模板、改装定义增加各自的发布版本，不新增武器实例属性表。

### B2-A：Admin 管理接口

管理接口归入现有 `/api/era/admin` 路由及权限体系，武器配置使用独立的 `equipment` 子路径，避免与已有技能草稿 `/configuration` 混淆。下列路由已在源码中实现；运行及权限联调尚未执行。

| 方法与相对路径（根为 `/api/era/admin/equipment`） | 功能 |
| --- | --- |
| GET `/weapon-templates` | 分页、筛选武器模板，返回当前目录版本 |
| GET `/weapon-templates/{id}` | 模板详情，包含基础属性、行为、表现键、槽位和模板候选池 |
| POST `/weapon-templates/{id}` | 创建或更新模板聚合，原子保存模板、槽位与池配置 |
| POST `/weapon-templates/{id}/disable` | 停止用于新生成，保留旧实例模板引用和属性读取 |
| POST `/weapon-templates/{id}/delete` | 删除未被资产或其他配置引用的模板；有引用时拒绝 |
| GET `/weapon-modifications` | 分页、按槽位等条件筛选公共改装定义 |
| GET `/weapon-modifications/{id}` | 改装详情及全部属性修正规则 |
| POST `/weapon-modifications/{id}` | 创建或更新改装定义，修正规则与定义一起原子保存 |
| POST `/weapon-modifications/{id}/delete` | 删除未引用的公共改装；池或实例仍引用时拒绝 |
| POST `/configuration/validate` | 校验拟发布配置及关联变更，返回错误和影响说明，不写数据 |
| POST `/configuration/publish` | 一次性提交多模板／改装的关联变更，统一校验并原子发布 |

模板详情返回 `Slots[].CandidateCount`，模板创建／更新接收该字段；例如枪管池有 8 个有效改装、数量设为 3，则每把新武器生成 3 个不同枪管候选。数量与权重是不同配置，不能只提供候选池编辑而遗漏数量字段。具体请求示意见共同设计的“每槽候选生成数量”。

首版管理写入采用统一原子发布流程：单模板和单改装保存是一次发布，关联批量变更由 publish 接口一次提交；本次未实现草稿、历史恢复或管理 UI。以后若扩展草稿，应使用独立暂存能力。
