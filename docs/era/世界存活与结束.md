# 世界存活与结束

## 范围与状态

本批接入世界心跳、有界后台检查、异常超时确认和统一结束转换。用户选择无活动宽限期默认为 **60 秒**，通过配置可调整。仍沿用独立 WorldInstanceId、既有 Redis 队伍与房主代次、SQL 协调锁和权限栅栏。

新增 Script0032，为世界添加 LastActiveAt、LastLifetimeCheckAt、TimeoutObservedAt、EndReason 和检查索引；历史 LastActiveAt 从 CreatedAt 回填，不改 Script0031，不改已有缓存结构或版本。旧终态世界的 EndReason 可以为空，不根据当前状态猜写历史原因。

本批仅完成源码与静态核对，未编译、运行测试、启动服务或执行迁移；此前用户确认通过的测试不覆盖本批新增实现。

## 存活与客户端入口

POST `/api/era/worlds/{worldInstanceId}/heartbeat` 接受 `HeartbeatEraWorldCommand`，正文仅含 MemberId 与由路由覆盖的 WorldInstanceId。沿用登录、EraClientSession、玩家预加载和 Mediator 事务。只允许该世界本人仍在继续的成员，且角色归属有效、未禁用；不能用其他人的 MemberId 续期。已离开成员被拒绝，终态世界不能靠心跳复活。

客户端在世界 Building／Ready 期间发送心跳，建议间隔默认 15 秒；客机也可以维持世界存活。心跳不要求客户端提交时间、房主代次或业务版本，因此迁移和 Redis 暂时不可用时仍可在 SQL 授权范围内确认存活；HTTP 客户端会话验证仍沿用项目现有规则。它不修改房主、代次、成员关系或限制，也不代替队伍重连和新房主 Recover。

响应为 `EraResponse<EraWorldHeartbeatDto>`，含 WorldInstanceId、LastActiveAt、HeartbeatIntervalSeconds 和 InactivityTimeoutSeconds。普通世界查询也返回这些策略值及 EndReason。LastActiveAt 使用服务器 UTC 时间，更新时不回退；世界登记、成功的权限写操作、有效世界心跳和后台确认到有效队伍房主／接管候补均可刷新活动时间。GET 不续期。

存活时间、检查时间和缺失观察属于运行元数据，更新不增加 World.Version；真正结束只递增一次业务版本。客户端不能因 LastActiveAt 变化推断成员、房主或装备有变化。

## 超时确认

`EraWorldLifetimeHostedService` 在网络能力启用时运行。默认每 10 秒扫描最多 64 个过宽限期的 Building／Ready 世界，按上次检查时间、世界 ID 排序；每个世界通过独立作用域的内部 `CheckEraWorldTimeoutCommand` 提交事务，没有公开的超时清理 HTTP 入口。多后端实例可以同时扫描，写入时重新加锁并检查时间，不依赖进程内锁或扫描快照。

确认过程如下：

1. 锁队伍协调行和世界行，重新检查活动时间、检查间隔及活动指针。
2. 在锁内推进 Redis 权限栅栏，再读取实时队伍。只有世界仍继续的成员与当前队伍的 PlayerId、CharacterId、MemberId 均匹配，且成员与队伍租约有效，才算有效世界成员。
3. 仍有正常房主或具备 CanHost 的继续成员时，保留世界并清除缺失观察；迁移候补也可以维持原世界，不重置限制或擅自完成房主恢复。
4. 首次成功确认没有可继续房主／候补时只记录 TimeoutObservedAt。之后再次成功检查，且与首次观察至少间隔默认 15 秒，才按超时结束。一次缺失不直接结束。
5. Redis 连接失败或队伍载荷损坏时返回 Unavailable，清空缺失观察并推迟；服务恢复后重新观察两次。故障持续时间不能直接作为“已确认没人继续”的时间。

60 秒是无活动宽限期，不是保证到点立刻结束。宽限之后还要完成分批扫描与至少两次缺失确认；默认 10 秒扫描间隔下，完全失联世界通常还需要额外的确认与调度时间。队伍租约过期、房主迁移、本机释放场景或一次心跳失败都不单独等于结束。

已经有新的有效心跳时，后台从新时间重新计算；超时结束先提交时，迟到心跳会被拒绝。队伍迁移、续期与超时检查使用相同 SQL 队伍锁及 Redis 栅栏：迁移先提交时，检查会看到新候补；结束先提交时，后来的房主恢复或心跳不能恢复旧世界。

## 统一结束与资产边界

`EraWorldLifecycle.Finish` 是当前唯一的结束状态转换，由主动结束、构建失败、最后成员离开和超时确认共同经 `FinishWorldAsync` 调用。调用者已持有队伍和世界锁，先失效未拾取资产，再统一设置终态、首次原因和结束时间，释放本世界活动成员索引；只有活动指针仍指向本世界时才清空。历史世界和成员保留，不删除防重依据。

结束原因显式区分 Abandoned、ConstructionFailed、LastMemberLeft、InactivityTimeout。重复结束不递增版本、不覆盖原原因和时间，不影响后来登记的新世界。更新均由外层 UnitOfWork 提交，保存失败会回滚世界、成员和活动指针，之后可安全重试。

世界排他锁和终态检查构成当前操作屏障，与装备读取限制的共享锁协调。结束后角色可在没有世界限制的状态下继续操作自己的背包和配装，世界结束不会销毁已拥有装备。后续已接入私人地面奖励及拾取，并在同一结束事务内失效 Available 记录和销毁对应无主 Ground 装备，见 [私人地面奖励与拾取](私人地面奖励与拾取.md)。该扩展含 Script0034 和新增测试源码，尚未运行验证；可恢复的分批清理仍未实现。

## 配置与验证

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `Era:World:HeartbeatIntervalSeconds` | 15 | 建议世界心跳间隔，允许 5～60 秒 |
| `Era:World:InactivityTimeoutSeconds` | 60 | 用户选择的无活动宽限期，至少三个心跳间隔，最多 3600 秒 |
| `Era:World:MissingConfirmationSeconds` | 15 | 缺失二次确认最短间隔，不小于扫描间隔，最多 300 秒 |
| `Era:World:ScanIntervalSeconds` | 10 | 后台扫描间隔，允许 1～60 秒 |
| `Era:World:BatchSize` | 64 | 每轮最大候选数量，允许 1～256 |

未写入或修改用户的 appsettings.json，缺省值由设置类提供。网络能力被配置关闭时，后台不自动结束世界。
