## 用例

| 文件 | 数量 | 验证内容 |
| --- | --- | --- |
| `EraIntegrationFixture.EquipmentQueries.cs` | 5 | 空角色查询不创建资产；玩家和位置隔离；历史属性原值；其他玩家角色拒绝；属性表缺行返回错误；目录删除定义后保留实例 |
| `EraIntegrationFixture.EquipmentOperations.cs` | 5 | 满分区原子替换及六维不变；满分区卸下拒绝；卸下后重放旧装配只返回历史；第二条条件 UPDATE 失败回滚第一条；保存回执失败回滚位置与版本 |
| `EraIntegrationFixture.EquipmentConcurrency.cs` | 2 | 同槽不同请求只有一个提交、另一个版本冲突；相同请求并发只提交一次、另一次返回原回执 |
| `EraIntegrationFixture.EquipmentConstraints.cs` | 4 | 同角色同槽唯一索引；每件装备只有一行护甲属性；角色与玩家归属复合外键；玩家范围的请求 ID 跨操作唯一 |

并发测试先让第一个请求取得玩家、角色和装备锁，在首条位置 UPDATE 前暂停；第二个独立请求到达玩家锁查询后释放第一个请求。使用信号及 30 秒取消上限协调，不依赖固定延时。测试结束前收束两个任务，再由基类清理数据；断言实际版本、位置和回执数量。

回滚测试通过仅作用于当前请求的 `DbCommandInterceptor` 设置失败点，仍执行真实 MySQL：一种给第二条 UPDATE 追加恒假条件，由零影响行数触发生产并发异常；另一种在最终回执保存批次执行 `SIGNAL SQLSTATE '45000'`，由服务器返回错误。用例同时断言失败前已执行的位置更新数量和影响行数，再从新连接范围核对整笔回滚，不能因请求提前失败而误报通过。

## 后续执行

经用户明确授权编译／执行后，可使用 .NET 10 SDK 运行：

```powershell
dotnet test src/Void.Bot.IntegrationTests/Void.Bot.IntegrationTests.csproj --filter "Category=ERAEquipmentIntegration"
```

既有测试基类从测试项目的 `appsettings.json` 派生 `appsetting_integration_test.json`，把连接中的 `database=db_void_bot` 替换为 `database=db_void_bot_integration_test`。执行前必须核对实际连接确实指向可清理的专用测试库；测试基类在构造时执行 DbUp、每例结束后用 Respawn 清表，并在整个集合结束时删除数据库。上述行为由既有框架提供，本次没有执行或修改该框架。测试数据覆盖 Script0029／Script0030 的真实建表约束，不能用缺迁移的旧库替代。

本组覆盖 Core 的 Mediator 与 SQL 集成链路，不包含 HTTP Controller 路由绑定、认证过滤器及真实客户端联调。世界限制、奖励、地面掉落等未实现功能仍按后端 TODO 待办，不由这组测试宣称完成。
