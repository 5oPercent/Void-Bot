## 1. 目录与身份

装备清单 `schemaVersion` 为 **3**。`weapons` 包含五个集合：`frameworks`、`templates`、`modifications`、`slotTypes`、`slotConfigurations`。发布版本仍为整套装备目录的 `version`，不是 SchemaVersion，也不是实例并发版本。

模板新增必填 `frameworkId`，删除 `behavior`；行为统一存放在框架能力配置。模板主表只保存基本信息与配置引用，全部基础属性值统一存入 `era_weapon_template_stat`；DTO 的 `baseStats` 是 `{ stat, value, effectAtZero, effectAtHundred }` 数组，不再是固定字段对象。评分效果端点直接保存在模板属性条目中，不再提供独立映射 ID 或管理接口；模板继续保存 `presentationKey`、`slotConfigurationId` 和 `compatibleSlots`。`presentationDriverKey` 选择流程，`presentationKey` 选择具体表现资源；名称与这两个键都不代替 Guid 身份。

框架结构如下，JSON 使用 camelCase，枚举使用数字；关系表内部 JSON 由后端使用 PascalCase 序列化，两者不混用：

```typescript
interface WeaponFramework {
  id: Guid;
  name: string; // 非空，最多 128 字符
  category: string; // 所属武器分类，1～64 字符，无首尾空白，默认“未分类”
  note: string; // 最多 2048 字符
  isEnabled: boolean; // 默认 true，控制能否新增模板引用
  presentationDriverKey: string; // 自定义 1～32 位 ASCII 字母、数字、点、下划线或短横线，区分大小写
  supplementaryStats: WeaponStat[]; // 只列五项补充属性，不列六项公共属性
  capabilities: WeaponCapability[];
}
```

各集合最多 10000 项；完整武器目录 UTF-8 序列化后不超过 1 MiB，Controller 请求体也不超过 1 MiB。能力最多 8 项，能力与补充属性均不得重复；未知字段、编号及格式不合法的驱动键拒绝保存。

分类表达“武器分类 → 框架 → 模板”：例如自动步枪下有适配框架、高冲击力框架；脉冲步枪下也可有独立的适配框架、速射框架。同名框架以各自 Guid 区分，独立配置。模板只保存 frameworkId，通过关联框架取得分类，不重复保存分类字段。category 可自由新增，不作为行为枚举或实体标识。表现驱动 key 由管理员填写，不再限定 Firearm／Bow／Crossbow／Melee；分类及 key 的修改均不推导或重置能力配置。

## 2. 属性契约

```typescript
interface WeaponStatValue {
  stat: WeaponStat; // 数字枚举，必填
  value: number; // 必填，有限数；按 stat 校验整数、范围和特殊值
  effectAtZero?: number | null; // 评分为 0 时的实际效果
  effectAtHundred?: number | null; // 评分为 100 时的实际效果
}
// WeaponTemplate.baseStats: WeaponStatValue[]
```

`era_weapon_template_stat` 的字段为 `template_id、stat、value、effect_at_zero、effect_at_hundred`，`(template_id, stat)` 为复合主键，外键限制删除。value 使用 DOUBLE，容量、储备、穿透仍必须满足整数规则，不允许小数或自动取整。框架的六项公共属性要求由统一契约固定包含，`era_weapon_framework_stat` 只列五项补充属性；模板属性条目集合必须恰好等于“六项公共属性＋框架补充属性”。

主表 `era_weapon_template` 不再含任何属性列；全部十一项使用同一种记录结构。重复属性、未知编号、空条目、缺少公共或适用补充属性、填写不适用属性均拒绝发布。DTO 继续使用 `baseStats` 表示基础值来源，不增加固定字段兼容读取。


| 名称 | 属性枚举名称 | 显式编号 | 模板基础值边界 |
| --- | --- | --- | --- |
| 伤害 | Damage | 1 | 有限数，0～1000000 |
| 频率 | Frequency | 2 | 有限数，>0 且 ≤1000000，次／秒 |
| 操控 | Handling | 9 | 有限数，0～100 |
| 容量 | LoadedCapacity | 3 | 整数，1～1000000 |
| 储备 | ReserveCapacity | 4 | 整数，-1～1000000 |
| 穿透 | Penetration | 6 | 整数，-1～1000000 |
| 精度 | Accuracy | 7 | 按框架要求存在；值为有限数，0～100 |
| 稳定 | Stability | 8 | 按框架要求存在；值为有限数，0～100 |
| 装填 | ReloadSpeed | 5 | 按框架要求存在；值为有限数，>0 且 ≤1000000，倍率 |
| 蓄力时间 | ChargeTime | 11 | 按框架要求存在；值为有限数，>0 且 ≤3600，秒 |
| 投射物速度 | ProjectileSpeed | 10 | 按框架要求存在；值为有限数，>0 且 ≤1000000，米／秒 |

按用户确认直接调整编号，**Penetration=6**，原 Range 已移除。Script0045 先删除旧射程修正，绝不将其数值转换为穿透修正；现有模板射程迁入框架最大距离配置。新契约需 Web／Godot 同步使用，不兼容旧目录。六项公共值必须有显式条目；补充条目的属性集合必须与框架 `supplementaryStats` 完全一致。不适用时不创建条目，不使用 null 或零占位。容量不允许 -1；储备 -1 表示无限备用资源，当前装载量仍然有限。穿透 0 表示最多一个有效目标，N 表示最多 N+1 个，-1 表示没有目标数量上限；不代表穿墙或忽略环境阻挡。

普通修正仍为 Flat=1、AddPercent=2。`value` 必须有限且绝对值 ≤1000000，AddPercent 必须 >-1；同一改装中的属性／运算组合不得重复。未适用的属性不能出现在模板关联的任一候选池改装中。无限值的计算、最终取整及运行弹药状态在客户端阶段接入，本轮仅完成后端配置校验。

## 3. 类型化能力

每项采用 `{ kind, 对应配置 }`，恰好一个非空配置；其他配置可以省略或为 null。空对象表示标记能力，并非任意参数袋。

| Kind | 非空配置字段 | 配置内容 | 必须启用的补充属性 |
| --- | --- | --- | --- |
| 1 Aim | aim | `{}` | 精度 7 |
| 2 Recoil | recoil | `{}` | 稳定 8 |
| 3 Reload | reload | `{ mode, baseSeconds }` | 装填 5 |
| 4 Charge | charge | `{ allowPartialRelease }` | 蓄力时间 11 |
| 5 Projectile | projectile | `{ maximumDistance }` | 投射物速度 10 |
| 6 MeleeHit | meleeHit | `{}` | 无 |
| 7 Firing | firing | `{ mode, burstCount }` | 无 |
| 8 Hitscan | hitscan | `{ maximumDistance }` | 无 |

- Reload.mode：Magazine=1、PerRound=2；baseSeconds 为有限正数，≤3600。实际装填时长由基准秒数除以最终装填倍率。
- Firing.mode：SemiAutomatic=1、Automatic=2、Burst=3、Charged=4。burstCount 为 1～64 的整数，非 Burst 时必须为 1；默认 1。Charged 与 Charge 能力必须同时存在或同时不存在。
- MaximumDistance：有限正数，≤1000000 米，分别表示最大飞行距离或检测距离；不是可改装属性。
- 蓄力配置当前只声明是否允许提前释放；未加入蓄力效果曲线、脚本或公式。动作资源和 Hit 绑定由模板表现资源承载，后续需接入资源清单验证。

后端按能力组合校验，与分类及驱动 key 无关：

| 命中方式 | 必选 | 可选／限制 |
| --- | --- | --- |
| 远程 | Firing；Hitscan／Projectile 二选一 | 可选 Aim、Recoil、Reload、Charge；不得 MeleeHit；Charged 与 Charge 同步 |
| 近战碰撞 | MeleeHit | 只可再加 Reload、Charge；不得 Aim、Recoil、Firing、Hitscan、Projectile |

这是后端通用配置合法性约束。客户端按自定义 key 查找已注册执行器；填写新 key 不会自动生成执行器。客户端仍须校验执行器实际支持的组合，未知 key 不得默认当成枪械执行。客户端能力／资源清单尚未接入后端发布校验。

## 4. 属性内的效果端点

两端值按“评分 0／100 时的实际效果”命名，不使用容易与评分范围混淆的 min／max。`value` 是基础属性值，`effectAtZero`、`effectAtHundred` 是该武器的效果换算配置，保存于同一属性行。

| 属性 | 端点含义 | 单位与边界 | 是否必填 |
| --- | --- | --- | --- |
| 精度 Accuracy | 散布角度 | 有限数，0～180 度 | 该属性存在时两个端点都必填 |
| 稳定 Stability | 后坐角度 | 有限数，0～180 度 | 该属性存在时两个端点都必填 |
| 操控 Handling | 掏出当前武器的时间 | 有限数，>0 且 ≤3600 秒 | 所有模板都必填；只影响掏出时间 |
| 其他八项属性 | 直接使用数值，无评分换算 | 使用各属性单位 | 两个端点均须为空或省略 |

100 分端点不得高于 0 分端点，允许相等。最终评分按 0～100 规则处理后，用 `effectAtZero + (effectAtHundred - effectAtZero) * score / 100` 换算实际效果。例如操控 50、端点 1 秒／0.2 秒，对应掏出时间 0.6 秒。操控不决定收起时间、瞄准时间或其他动作耗时。

同一框架下不同模板可以有不同端点。框架只定义能力、适用属性及行为配置；Aim／Recoil 是标记能力，不存评分端点。删除独立 `era_weapon_stat_mapping` 表及其实体、DTO、效果枚举和增删改查接口，模板和框架都没有 `statMappingId`。缺少任一评分端点、填入非有限值、顺序错误、单位边界错误或为其他属性配置端点，均拒绝发布。

## 5. 管理接口与发布

前缀 `/api/era/admin/equipment`，沿用现有后台认证和端点权限；无需游戏会话。普通业务响应仍需检查正文 `code`，不能仅检查 HTTP 200。

| 方法 | 相对路径 | 请求／结果 |
| --- | --- | --- |
| GET | /weapon-frameworks | pageIndex≥1，pageSize=1～100；可选 search≤128、category≤64、presentationDriverKey≤32、isEnabled；分类及 key 无首尾空白，精确匹配，key 区分大小写；data 为分页，version 在顶层 |
| GET | /weapon-frameworks/{id} | data 为框架；顶层返回 version 和 templateIds 引用列表 |
| POST | /weapon-frameworks | `{ expectedManifestVersion, framework }`；服务器分配新 Guid，可用于创建／复制 |
| POST | /weapon-frameworks/{id} | 同上；路由覆盖正文 id，完整更新／保存 |
| POST | /weapon-frameworks/{id}/disable | `{ expectedManifestVersion }`；保留现有引用，只禁止新增模板引用 |
| POST | /weapon-frameworks/{id}/delete | `{ expectedManifestVersion }`；有模板引用返回 409，不级联删除 |
| POST | /configuration/validate | `{ configuration }`；data.errors 为空才代表预检有效 |
| POST | /configuration/publish | `{ expectedManifestVersion, configuration }`；一次提交全部五个集合 |

写入返回 `data: { savedId?, version, configuration }`，configuration 是完整新武器目录。写入成功就是发布，不另设框架草稿。版本不匹配返回 409；成功在共享版本锁和事务内只加一次版本，失败整体回滚。停用框架不改变模板 `isGenerationEnabled`，现有模板继续可生成；新模板不能引用停用框架。

框架自身校验能力与补充属性组合；每个引用模板校验适用属性及其评分端点。没有模板的框架不需要属性数值或端点。仅改框架名称、说明、启用状态或普通数值不扫描无关资产。删除／变更模板引用、缩减适用属性、改变驱动或能力集合、改装新增属性等潜在破坏性调整，会校验受影响的实例和待发奖励计划；旧候选即使未选中或已不在当前候选池，也不能失效。发布不重抽候选，不改资产并发版本。

需要同时改变框架属性集合、模板值、属性端点和候选池时，先在 Web 草稿合成完整目录，再用 validate／publish 原子提交；单项保存不能经过无效中间状态。Web 批量读取须从五类分页接口取齐同一 version，版本变化后重新读取。
