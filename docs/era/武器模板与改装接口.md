数据访问遵循 Service → DataProvider → IRepository → DbContext。ERA 的关系数据 DataProvider 注入实体仓储，参数化行锁、即时条件更新与批量删除经 IRepository 执行；Service 使用领域并发异常，不依赖 EF。普通资产事务仍由 Mediator 工作单元统一提交。既有 Redis 队伍提交的独立 SQL 协调事务也收口到非泛型 IRepository，其单例实现不持有作用域 DbContext，不提交调用方资产事务。

保存与发布均保留共享目录版本锁，只更新有变化的记录；方案槽位／候选池及属性修正子记录只在对应内容变化时替换。名称、图标、停用和普通数值调整不扫描玩家资产或待发奖励。删除模板、删除／改类型的改装、缩减兼容部位等可能使已有引用失效的调整，按受影响编号查询资产；武器额外检查移除蓄力／投射物属性及新增相应修正的兼容性。待发计划仍为 JSON，仅在可能破坏引用时读取。护甲和武器共用改装选择流程及加权不重复抽样，接口字段与回执格式保持原样。

`PresentationKey` 仅标识整枪表现，客户端自行映射本地模型资源。动态改装槽位只改变属性，不改变模型或射击模式。武器行为随公共模板保存，不增加机匣、固定框架表或可执行脚本。模板不设置武器大类字段；未来需要规则区分时按框架设计，当前由类型化行为配置表达执行方式。Kind 的移除在此前部署前完成，已部署脚本没有该列。

## 稳定协议值

原有护甲槽和品阶数值不变。C# 公共类型更名为 `EraEquipmentSlot`、`EraEquipmentGrade`，JSON 仍使用数字。

| 类型 | 协议值 |
| --- | --- |
| 装备类型 | Armor=1、Weapon=2 |
| 背包筛选 | EquipmentType=1 筛选护甲，EquipmentType=2 筛选武器；不筛选则返回全部 |
| 穿戴位置 | 原护甲 1～6；Weapon1=101、Weapon2=102、Weapon3=103 |
| 内部改装槽 | 槽位 `SlotId` 使用 UUID，适配类型 `SlotTypeId` 引用类型字典 |
| 修正运算 | Flat=1、AddPercent=2；`0.2` 表示 +20%，`-0.2` 表示 -20% |
| 开火模式 | SemiAutomatic=1、Automatic=2、Burst=3、Charged=4 |
| 命中模式 | Hitscan=1、Projectile=2 |
| 装填模式 | Magazine=1、PerRound=2 |
| 操作回执 | 保留既有操作值；SelectWeaponModification=5 |

十一项属性按顺序为 Damage=1、Frequency=2、LoadedCapacity=3、ReserveCapacity=4、ReloadSpeed=5、Range=6、Accuracy=7、Stability=8、Handling=9、ProjectileSpeed=10、ChargeTime=11。伤害、频率、装填速度系数和射程为有限正数；装载容量为正整数，储备上限为非负整数，评分为 0～100。频率单位为次/秒，距离为米，时间为秒，投射物速度为米/秒。

模板 Accuracy、Stability、Handling 填写 0～100 的基础评分，非百分比，也不填写角度或秒数。`StatMappingId` 必须引用本目录 `Weapons.StatMappings` 中的共享配置，多个模板可引用同一 Guid；实例不复制端点。端点由后端配置、校验并随完整目录发布，客户端不把平衡值保存在 Godot Resource 中，调整端点无需更新客户端。

`EraWeaponStatMappingDto` 包含 Id、Name，以及 SpreadDegreesAtZero／AtHundred、RecoilDegreesAtZero／AtHundred、ReadySecondsAtZero／AtHundred、AimSecondsAtZero／AtHundred 八个端点。Zero 对应 0 分，Hundred 对应 100 分，按 `zero + (hundred - zero) × 最终评分 / 100` 换算。角度为 0～180 度，动作时间为大于 0、至多 3600 秒，所有值必须有限，100 分端点不能大于 0 分端点。引用缺失、重复身份或非法端点拒绝发布；被模板引用的配置不能单独删除。

共享配置支持 Admin `weapon-stat-mappings` 独立分页／详情／保存／删除，也可通过 `configuration/validate`／`configuration/publish` 的 `Configuration.StatMappings` 与 Templates、Modifications、SlotTypes、SlotConfigurations 一起原子发布；不增加独立发布版本。单项操作保留其余目录对象，被任一模板引用的属性映射配置删除返回 `era.weapon_reference_conflict`。游戏端从 manifest 读取并固定本局版本，更新在下局采用，当前实例选择仍使用本局目录计算。初始步枪端点暂用散布 3→1 度、后坐 2→0.5 度、就绪 1→0.35 秒、瞄准 0.5→0.15 秒；文档示例不自动创建生产配置。

后端已移除 Behavior 中的 BaseSpreadDegrees、BaseRecoilDegrees、BaseReadySeconds、BaseAimSeconds；BaseReloadSeconds 继续保留，ReloadSpeed 为速度系数，1.2 表示速度提高 20%，实际装填秒数为 BaseReloadSeconds / ReloadSpeed。实体属性 XML 备注同步说明各属性的填写单位及语义。

这四个字段原本位于 behavior_payload JSON 中，没有独立数据库列；此前部署已包含该调整。本轮属性映射命名变更使用新增的 Script0039，不重写已部署脚本。

`ProjectileSpeed` 只在 Projectile 模式下有值，`ChargeTime` 只在 Charged 模式下有值；其他模式必须为 null。不能用 0 表示不适用，也不能为不支持的属性配置修正。

客户端按共同设计求值：`(Base + sum(Flat)) * (1 + sum(AddPercent))`，全部修正汇总后统一做边界限制，容量最后向下取整。装填时长为 `BaseReloadSeconds / ReloadSpeed`；例如系数 1 降低 20% 后，2.4 秒变为 3 秒。后端不落库最终属性，不执行射击、扣弹、装填进度或逐帧战斗。评分如何映射散布、后坐和动作时长，以及本局配置切换与弹药超限处理，仍需客户端权威执行层落实。

## Admin 管理接口

根路径 `/api/era/admin/equipment`，继承现有 `[Authorize]`、`EraClientSession`、`Security`。管理路径已在游戏会话过滤器中豁免，无需 X-ERA-Client-Id。管理 Action 没有 `SkipPermissionCheck`；普通登录玩家无管理权限。通过现有 endpoint 权限系统授予对应路径与 HTTP 方法，超级管理员沿用现有机制。上线后仍需验证实际账号的 401/403 行为。

单项保存同样是一次发布，没有草稿状态；关联修改推荐一次批量发布。批量 Configuration 是完整目标目录，遗漏的定义视为删除，仍执行引用保护。保存成功统一返回 `Data.Version`、`Data.Configuration`；审计操作者、时间沿用装备配置行。预检不预留版本，正式发布始终再次检查。

模板、护甲定义、公共改装定义及全部关联 ID 均为非空 Guid，JSON 使用标准 Guid 字符串，Admin 路由使用 `{id:guid}`；配置 DTO 的 ID 默认使用 `Guid.NewGuid()`，新建和新增槽位不发送 ID；更新路由 ID 覆盖正文 ID，保存按 ID 新增或替换。显式空 Guid 由 Validators 拒绝。创建成功返回 `SavedId` 与完整目录。写入契约及嵌套配置拒绝未知 JSON 字段；属性、方案槽位及引用规则由服务统一校验。分页默认 1/20，PageSize 最大 100，Search 最长 128。HTTP 管理请求上限沿用 1 MiB；整份序列化武器目录预算 1 MiB，模板与公共改装各最多 10000 条。

每槽 `CandidateCount` 必填，范围 1～16，池最多 256 项。池内改装必须互不重复、适配类型一致、权重为正，权重总和不超过 int.MaxValue，兼容项数量至少等于 CandidateCount。不满足时整次发布失败，不缩减数量、不重复填充。生成按权重不放回，抽取顺序作为实例顺序，首个抽到的候选初始选中；16 是技术限制，不是每把枪的默认数量。

新建使用集合 POST，不提供对象或新槽位 ID；更新使用 `/{id}`，方案内新增槽位也省略 ID。DTO 默认使用 `Guid.NewGuid()` 生成编号；Validators 校验显式空 Guid，保存服务不补正输入。完整目录沿用统一预检和原子发布流程。

## 玩家查询、选择和可信主机读取

`GET /api/era/manifest/equipment` 已提供完整目录，返回统一 Version、原护甲目录和 Weapons.Templates／Modifications／StatMappings／SlotTypes／SlotConfigurations。该非管理路径仍要求有效游戏会话。纯 Web 也可完整遍历五类 Admin 分页，以所有响应 Version 一致为前提组装完整武器目录；必须包含全部五类配置。方案池会包含新生成配置，移出池但被旧实例使用的公共改装仍保留在 Modifications。

既有本人角色 `GET /api/era/characters/{characterId}/equipment` 和 `/inventory` 返回武器及其 `Weapon.Slots[].Candidates/SelectedCandidateId`，并关联当前 `WeaponTemplate`。`/inventory?equipmentType=2` 筛选同一背包内的武器；可选 Slot 表示目标穿戴位置，只根据当前模板 CompatibleSlots 返回兼容候选，一件装备可以出现在多个位置的候选中，但总数只计一次。所有类型共享 120 件容量，TotalInventoryCount 始终包含全部武器与护甲，不随筛选变化。FilterEquipmentType、FilterSlot 返回本次筛选条件，快照返回九个穿戴位置，不返回背包分类计数。模板缺失的实例保留在未按目标槽位筛选的列表中供降级展示，不进入可穿戴候选。武器的护甲生成版本为 0、护甲属性为空默认对象，客户端先按 EquipmentType 分派。

选择接口：`POST /api/era/characters/{characterId}/equipment/{equipmentInstanceId}/modifications/select`，正文示意：

```json
{
  "requestId": "11111111-1111-1111-1111-111111111111",
  "candidateId": "22222222-2222-2222-2222-222222222222",
  "expectedManifestVersion": 8,
  "expectedEquipmentVersion": 4,
  "expectedItemVersion": 1,
  "slotId": "60000000-0000-0000-0000-000000000002"
}
```

CandidateId 必须取自这把武器、这个槽的已保存候选。该接口不接收候选集合或最终属性，不能改仓库或他人武器。服务检查本人角色、禁用状态、目录／角色装备／实例版本、武器所在位置；已穿武器遵守世界装备操作限制。战斗中的逐帧状态检查由游戏权威端负责，后端没有未射击／未装填的实时证据。

改变选择时只更新选择记录、实例 Version、角色 EquipmentVersion；同事务创建回执并入通知 outbox。重复选当前候选保存成功回执，版本不增加、不发资产变化通知。RequestId 在玩家范围防重，相同参数返回原回执并标记 IsReplay=true，同 ID 不同参数返回冲突。响应 `Data.State.ManifestVersion` 标明原结果使用的目录，历史回执不能覆盖客户端较新的资产或配置。

`GET /api/era/worlds/{worldInstanceId}/equipment?memberId=...&authorityEpoch=...` 供当前主机读取。服务同时核对 SQL 世界成员、Ready 状态、主机代次及 Redis 当前队伍租约，返回继续参与成员的已穿装备、角色装备版本与目录版本，不返回背包或仓库。主机迁移、租约过期、成员状态或目录在读取期间变化时拒绝本次结果，重新查询。

## 版本、奖励与通知

| 字段 | 含义与变化 |
| --- | --- |
| Manifest.Version | 唯一公共目录发布版本；保存模板／改装或批量发布成功增加一次 |
| Instance.GenerationManifestVersion | 生成时目录版本，只追踪来源，不冻结模板基础值 |
| Instance.Version | 位置、归属或选择实际变化时递增；配置发布不增加 |
| Character.EquipmentVersion | 角色资产状态并发版本；配置发布不增加 |

方案含零个或多个槽位，同类型允许多个具体槽；槽位身份为 UUID，数量不由枚举决定。模板引用方案，生成器从方案生成实例快照。方案增删、排序、换池或模板换方案不改变已有实例槽位；规则详见 [武器改装槽位方案](武器改装槽位方案.md)。

模板基础值和公共改装效果更新后，旧实例在采用新目录时使用新数值；池、权重或 CandidateCount 变化只影响新生成。不能根据最新池过滤旧候选，也不能按最新数量补齐或截断旧集合。停用模板只阻止新计划生成，不阻止既有固定计划发放及旧实例读取。

奖励继续通过已有内部准备／发放 Command 和地面奖励 Command 创建，不增加玩家直接造枪入口。固定计划保存实际候选及选择，背包满后的重试不会重抽；发放时共享锁定目录，管理员发布同时保护待发计划引用。奖励配置发布也核验当前装备定义，避免把奖励池指向已删除模板。拾取、丢出、分享和世界清理保留候选与实例身份。

资产变化通知复用现有 Social outbox，提交后投递 `eventType=era.equipment.changed`，ResourceId 为角色 ID，ResourceVersion 为 EquipmentVersion，CorrelationId 为请求／奖励事件 ID；本人和当前 SQL 世界主机账号接收。通知只触发补查询，不作为资产数据或授权凭证。客户端应处理重复、延迟与失联重连后的主动补查。

本次配置变化采用目录版本重查，没有新增广播频道。管理响应立即给出新版本；客户端在进入／恢复世界、提交操作前和收到目录版本冲突时读取 manifest。游戏主机组织本局统一目录的切换边界，不能仅凭角色 EquipmentVersion 未变化就跳过重新计算。
