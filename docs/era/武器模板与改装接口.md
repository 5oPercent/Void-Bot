# ERA 武器模板与改装后端接口

更新日期：2026-10-24。本文对应本次后端源码实现；尚未编译、运行测试或应用迁移。

数据访问遵循 Service → DataProvider → IRepository → DbContext。ERA 的关系数据 DataProvider 注入实体仓储，参数化行锁、即时条件更新与批量删除经 IRepository 执行；Service 使用领域并发异常，不依赖 EF。普通资产事务仍由 Mediator 工作单元统一提交。既有 Redis 队伍提交的独立 SQL 协调事务也收口到非泛型 IRepository，其单例实现不持有作用域 DbContext，不提交调用方资产事务。

## 持久化与边界

新增 DbUp 脚本：`src/Void.Bot.Core/Dbup/Scripts/Script0035_init_era_weapons.sql` 建立八张武器表；`Script0037_remove_era_equipment_inventory_classification.sql` 删除原有背包分类列并调整查询索引。`Script0038_use_guid_equipment_definitions.sql` 将共用装备定义引用转为 Guid，并同步原护甲目录、奖励配置、奖励计划及装备操作回执中的定义引用。原有标准 Guid 保留，旧业务字符串按固定规则映射，实例与候选身份不重抽；临时迁移函数完成后删除。既有迁移顺序保持不变。不创建正式模板、奖励来源或玩家武器。

| 表 | 保存内容 |
| --- | --- |
| `era_weapon_stat_effect_profile` | 共享评分效果配置 Guid、名称、四组 0／100 分端点 |
| `era_weapon_template` | 当前共享基础属性、类型化行为、表现键、可穿位置、是否允许新生成 |
| `era_weapon_template_mod_slot` | 模板的五个槽、每槽 `CandidateCount`、显示顺序 |
| `era_weapon_mod_definition` | 公共改装的稳定 ID、所属槽、名称说明与图标 |
| `era_weapon_mod_stat_modifier` | 公共改装的属性、运算与有符号修正值 |
| `era_weapon_template_mod_pool` | 新生成使用的候选池及权重 |
| `era_weapon_mod_candidate` | 每把武器生成后固定的候选 ID、槽、改装定义引用与顺序 |
| `era_weapon_mod_selection` | 每把武器每槽当前选中候选的 ID |

实例继续使用 `era_equipment_instance`，不新增实例属性快照。武器与护甲放在同一个角色背包，共享 120 件容量；实例只用 Location 与 EquippedSlot 表达位置，不保存部位分类。装备类型由 EquipmentType 标识，适用穿戴位置由模板 CompatibleSlots 定义。数据库以复合外键保证选中候选属于同一武器、同一槽；候选不引用可变的模板池行。模板删除还检查资产、待发奖励计划和当前奖励池引用；候选使用的改装不能删除、改槽，不能通过发布隐式改变旧候选集合。已经销毁但保留历史记录的资产也保留引用保护。

ID 默认使用 Guid；名称、图标和表现映射键保留字符串，不承担实体身份，不再为装备定义 ID 单设字符串排序规则。实体关系配置集中在 `EraWeaponEntityConfiguration`，只保留复合键、唯一约束及外键关系。

`PresentationKey` 仅标识整枪表现，客户端自行映射本地模型资源。五个改装槽只改变属性，不改变模型或射击模式。武器行为随公共模板保存，不增加机匣、固定框架表或可执行脚本。模板不设置武器大类字段；未来需要规则区分时按框架设计，当前由类型化行为配置表达执行方式。后端尚未部署，直接从建表脚本中移除 kind 列，不新增清理脚本。

## 稳定协议值

原有护甲槽和品阶数值不变。C# 公共类型更名为 `EraEquipmentSlot`、`EraEquipmentGrade`，JSON 仍使用数字。

| 类型 | 协议值 |
| --- | --- |
| 装备类型 | Armor=1、Weapon=2 |
| 背包筛选 | EquipmentType=1 筛选护甲，EquipmentType=2 筛选武器；不筛选则返回全部 |
| 穿戴位置 | 原护甲 1～6；Weapon1=101、Weapon2=102、Weapon3=103 |
| 内部改装槽 | Optic=1、Barrel=2、Grip=3、Magazine=4、Stock=5 |
| 修正运算 | Flat=1、AddPercent=2；`0.2` 表示 +20%，`-0.2` 表示 -20% |
| 开火模式 | SemiAutomatic=1、Automatic=2、Burst=3、Charged=4 |
| 命中模式 | Hitscan=1、Projectile=2 |
| 装填模式 | Magazine=1、PerRound=2 |
| 操作回执 | 保留既有操作值；SelectWeaponModification=5 |

十一项属性按顺序为 Damage=1、Frequency=2、LoadedCapacity=3、ReserveCapacity=4、ReloadSpeed=5、Range=6、Accuracy=7、Stability=8、Handling=9、ProjectileSpeed=10、ChargeTime=11。伤害、频率、装填速度系数和射程为有限正数；装载容量为正整数，储备上限为非负整数，评分为 0～100。频率单位为次/秒，距离为米，时间为秒，投射物速度为米/秒。

模板 Accuracy、Stability、Handling 填写 0～100 的基础评分，非百分比，也不填写角度或秒数。`StatEffectProfileId` 必须引用本目录 `Weapons.StatEffectProfiles` 中的共享配置，多个模板可引用同一 Guid；实例不复制端点。端点由后端配置、校验并随完整目录发布，客户端不把平衡值保存在 Godot Resource 中，调整端点无需更新客户端。

`EraWeaponStatEffectProfileDto` 包含 Id、Name，以及 SpreadDegreesAtZero／AtHundred、RecoilDegreesAtZero／AtHundred、ReadySecondsAtZero／AtHundred、AimSecondsAtZero／AtHundred 八个端点。Zero 对应 0 分，Hundred 对应 100 分，按 `zero + (hundred - zero) × 最终评分 / 100` 换算。角度为 0～180 度，动作时间为大于 0、至多 3600 秒，所有值必须有限，100 分端点不能大于 0 分端点。引用缺失、重复身份或非法端点拒绝发布；被模板引用的配置不能单独删除。

共享配置通过现有 Admin `configuration/validate`／`configuration/publish` 的 `Configuration.StatEffectProfiles` 维护，与 Templates、Modifications 一起原子发布；不增加独立发布版本。单项模板／改装管理会保留已有共享配置。游戏端从 manifest 读取并固定本局版本，更新在下局采用，当前实例选择仍使用本局目录计算。初始步枪端点暂用散布 3→1 度、后坐 2→0.5 度、就绪 1→0.35 秒、瞄准 0.5→0.15 秒；文档示例不自动创建生产配置。

后端已移除 Behavior 中的 BaseSpreadDegrees、BaseRecoilDegrees、BaseReadySeconds、BaseAimSeconds；BaseReloadSeconds 继续保留，ReloadSpeed 为速度系数，1.2 表示速度提高 20%，实际装填秒数为 BaseReloadSeconds / ReloadSpeed。实体属性 XML 备注同步说明各属性的填写单位及语义。

这四个字段原本位于 behavior_payload JSON 中，没有独立数据库列；当前后端尚未部署，因此直接调整现有契约与序列化内容，不新增旧数据清理脚本。

`ProjectileSpeed` 只在 Projectile 模式下有值，`ChargeTime` 只在 Charged 模式下有值；其他模式必须为 null。不能用 0 表示不适用，也不能为不支持的属性配置修正。

客户端按共同设计求值：`(Base + sum(Flat)) * (1 + sum(AddPercent))`，全部修正汇总后统一做边界限制，容量最后向下取整。装填时长为 `BaseReloadSeconds / ReloadSpeed`；例如系数 1 降低 20% 后，2.4 秒变为 3 秒。后端不落库最终属性，不执行射击、扣弹、装填进度或逐帧战斗。评分如何映射散布、后坐和动作时长，以及本局配置切换与弹药超限处理，仍需客户端权威执行层落实。

## Admin 管理接口

根路径 `/api/era/admin/equipment`，继承现有 `[Authorize]`、`EraClientSession`、`Security`。这些 Action 没有 `SkipPermissionCheck`；普通登录玩家无管理权限。通过现有 endpoint 权限系统授予对应路径与 HTTP 方法，超级管理员沿用现有机制。上线后仍需验证实际账号的 401/403 行为。

| 方法与相对路径 | 输入与结果 |
| --- | --- |
| GET `/weapon-templates` | PageIndex、PageSize、Search；分页数据及顶层 Version |
| GET `/weapon-templates/{id}` | 模板完整聚合及顶层 Version |
| POST `/weapon-templates/{id}` | ExpectedManifestVersion、Template；创建或整项替换模板聚合 |
| POST `/weapon-templates/{id}/disable` | ExpectedManifestVersion；禁止新生成，旧实例继续读取及使用 |
| POST `/weapon-templates/{id}/delete` | ExpectedManifestVersion；仅允许删除无引用模板 |
| GET `/weapon-modifications` | PageIndex、PageSize、Search、可选 Slot；分页数据及 Version |
| GET `/weapon-modifications/{id}` | 公共改装及全部修正规则、Version |
| POST `/weapon-modifications/{id}` | ExpectedManifestVersion、Modification；创建或整项替换定义 |
| POST `/weapon-modifications/{id}/delete` | ExpectedManifestVersion；池、资产或待发计划引用时拒绝 |
| POST `/configuration/validate` | Configuration；返回 Data.Version、Data.Errors；只读预检 |
| POST `/configuration/publish` | ExpectedManifestVersion、Configuration；整份武器目录替换并原子发布 |

单项保存同样是一次发布，没有草稿状态；关联修改推荐一次批量发布。批量 Configuration 是完整目标目录，遗漏的定义视为删除，仍执行引用保护。保存成功统一返回 `Data.Version`、`Data.Configuration`；审计操作者、时间沿用装备配置行。预检不预留版本，正式发布始终再次检查。

模板、护甲定义、公共改装定义及全部关联 ID 均为非空 Guid，JSON 使用标准 Guid 字符串，Admin 路由使用 `{id:guid}`；创建时由调用方生成 Guid，后续更新沿用原 ID。路由 ID 覆盖正文对应 ID。写入契约及嵌套配置拒绝未知 JSON 字段；属性、五槽及引用规则由服务统一校验。分页默认 1/20，PageSize 最大 100，Search 最长 128。HTTP 管理请求上限沿用 1 MiB；整份序列化武器目录预算 1 MiB，模板与公共改装各最多 10000 条。

每槽 `CandidateCount` 必填，范围 1～16，池最多 256 项。池内改装必须互不重复、槽位一致、权重为正，权重总和不超过 int.MaxValue，兼容项数量至少等于 CandidateCount。不满足时整次发布失败，不缩减数量、不重复填充。生成按权重不放回，抽取顺序作为实例顺序，首个抽到的候选初始选中；16 是技术限制，不是每把枪的默认数量。

## 玩家查询、选择和可信主机读取

`GET /api/era/manifest/equipment` 返回统一 Version、原护甲目录和 Weapons.Templates／Modifications。模板池会包含新生成配置，移出池但被旧实例使用的公共改装仍保留在 Modifications。

既有本人角色 `GET /api/era/characters/{characterId}/equipment` 和 `/inventory` 返回武器及其 `Weapon.Slots[].Candidates/SelectedCandidateId`，并关联当前 `WeaponTemplate`。`/inventory?equipmentType=2` 筛选同一背包内的武器；可选 Slot 表示目标穿戴位置，只根据当前模板 CompatibleSlots 返回兼容候选，一件装备可以出现在多个位置的候选中，但总数只计一次。所有类型共享 120 件容量，TotalInventoryCount 始终包含全部武器与护甲，不随筛选变化。FilterEquipmentType、FilterSlot 返回本次筛选条件，快照返回九个穿戴位置，不返回背包分类计数。模板缺失的实例保留在未按目标槽位筛选的列表中供降级展示，不进入可穿戴候选。武器的护甲生成版本为 0、护甲属性为空默认对象，客户端先按 EquipmentType 分派。

选择接口：`POST /api/era/characters/{characterId}/equipment/{equipmentId}/modifications/select`，正文示意：

```json
{
  "requestId": "11111111-1111-1111-1111-111111111111",
  "slot": 2,
  "candidateId": "22222222-2222-2222-2222-222222222222",
  "expectedManifestVersion": 8,
  "expectedEquipmentVersion": 4,
  "expectedItemVersion": 1
}
```

CandidateId 必须取自这把武器、这个槽的已保存候选。该接口不接收候选集合或最终属性，不能改仓库或他人武器。服务检查本人角色、禁用状态、目录／角色装备／实例版本、武器所在位置；已穿武器遵守世界装备操作限制。战斗中的逐帧状态检查由游戏权威端负责，后端没有未射击／未装填的实时证据。

改变选择时只更新选择记录、实例 Version、角色 EquipmentVersion；同事务创建回执并入通知 outbox。重复选当前候选保存成功回执，版本不增加、不发资产变化通知。RequestId 在玩家范围防重，相同参数返回原回执并标记 IsReplay=true，同 ID 不同参数返回冲突。响应 `Data.State.ManifestVersion` 标明原结果使用的目录，历史回执不能覆盖客户端较新的资产或配置。

`GET /api/era/worlds/{worldInstanceId}/equipment?memberId=...&authorityEpoch=...` 供当前主机读取。服务同时核对 SQL 世界成员、Ready 状态、主机代次及 Redis 当前队伍租约，返回继续参与成员的已穿装备、角色装备版本与目录版本，不返回背包或仓库。主机迁移、租约过期、成员状态或目录在读取期间变化时拒绝本次结果，重新查询。

## 版本、奖励与通知

| 字段 | 含义与变化 |
| --- | --- |
| Manifest.Version | 唯一公共目录发布版本；保存模板／改装或批量发布成功增加一次 |
| Instance.DefinitionVersion | 生成时目录版本，只追踪来源，不冻结模板基础值 |
| Instance.Version | 位置、归属或选择实际变化时递增；配置发布不增加 |
| Character.EquipmentVersion | 角色资产状态并发版本；配置发布不增加 |

模板基础值和公共改装效果更新后，旧实例在采用新目录时使用新数值；池、权重或 CandidateCount 变化只影响新生成。不能根据最新池过滤旧候选，也不能按最新数量补齐或截断旧集合。停用模板只阻止新计划生成，不阻止既有固定计划发放及旧实例读取。

奖励继续通过已有内部准备／发放 Command 和地面奖励 Command 创建，不增加玩家直接造枪入口。固定计划保存实际候选及选择，背包满后的重试不会重抽；发放时共享锁定目录，管理员发布同时保护待发计划引用。奖励配置发布也核验当前装备定义，避免把奖励池指向已删除模板。拾取、丢出、分享和世界清理保留候选与实例身份。

资产变化通知复用现有 Social outbox，提交后投递 `eventType=era.equipment.changed`，ResourceId 为角色 ID，ResourceVersion 为 EquipmentVersion，CorrelationId 为请求／奖励事件 ID；本人和当前 SQL 世界主机账号接收。通知只触发补查询，不作为资产数据或授权凭证。客户端应处理重复、延迟与失联重连后的主动补查。

本次配置变化采用目录版本重查，没有新增广播频道。管理响应立即给出新版本；客户端在进入／恢复世界、提交操作前和收到目录版本冲突时读取 manifest。游戏主机组织本局统一目录的切换边界，不能仅凭角色 EquipmentVersion 未变化就跳过重新计算。
