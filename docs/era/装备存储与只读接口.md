## 数据存储

新增 `Script0029_init_era_equipment.sql`，既有迁移保持不变：

| 数据 | 用途 |
| --- | --- |
| `era_equipment_configuration` | 固定单行保存整份目录的版本及 JSON 载荷，复用技能配置的存储方式 |
| `era_equipment_instance` | 实例身份、定义与生成时目录版本、品阶、归属、位置、唯一背包分区、已穿槽位及实例并发版本 |
| `era_armor_instance_data` | 以 EquipmentId 为主键，保存唯一一份六维最终整数及生成规则版本 |
| `era_character.equipment_version` | 背包和已穿装备共享的独立状态版本，初始为 0，不复用角色资料 Version |

目录固定行 ID 为 `30000000-0000-0000-0000-000000000001`，初始行版本为 `1`，载荷为 `{"SchemaVersion":1,"Definitions":[]}`。空目录合法，不自动添加示例装备或给角色补发资产。目录发布入口和实际定义内容后续接入；读取不会创建或更新这条记录。

目录采用 PascalCase JSON 存储，与现有技能配置默认序列化方式一致。载荷中的 Version、生成规则和容量不作为可信来源：目录版本取存储行，生成规则取后端生成器，分区容量固定取本轮规则。

定义包含稳定 Id、Name、Icon、Note、InventorySlot 及 CompatibleSlots。Id 区分大小写并在一份目录内唯一；兼容列表必须非空、无重复且包含定义的唯一背包分区。Icon 是资源映射引用，可为空，不预填客户端路径。实例保存自己的 InventorySlot，不因最新定义变化被重新归类。

实例的 DefinitionVersion 记录生成时目录版本；本批只保存当前目录，展示定义按当前 Id 匹配，不提供历史目录查询。定义移除、目录缺失或目录载荷无效时，角色资产查询仍返回保存的实例与六维，Definition 为空，客户端按 DefinitionId 降级显示。

数据库保证同角色同已穿槽位唯一、单件护甲属性唯一，并通过角色与玩家的复合外键阻止有效非空归属配对错乱。关联使用限制删除，不级联销毁历史资产。由于现有 MySQL 配置兼容 8.0.3，不依赖后续版本才强制执行的 CHECK；位置字段组合与容量必须由后续写操作在同一事务内维护：

| 位置 | OwnerPlayerId | CharacterId | EquippedSlot |
| --- | --- | --- | --- |
| Ground / Destroyed | 空 | 空 | 空 |
| Inventory | 有值 | 有值 | 空 |
| Equipped | 有值 | 有值 | 有值 |
| Warehouse | 有值 | 空 | 空 |

地面、仓库及销毁仅预留本体状态，本批角色查询不返回这些位置。地面生命周期、分享资格及奖励回执尚未建立。

## 只读接口

| 方法与路径 | Request | Data |
| --- | --- | --- |
| GET `/api/era/manifest/equipment` | GetEraEquipmentManifestRequest | EraEquipmentManifestDto |
| GET `/api/era/characters/{characterId}/equipment` | GetEraCharacterEquipmentRequest | EraCharacterEquipmentStateDto |
| GET `/api/era/characters/{characterId}/inventory` | GetEraCharacterInventoryRequest，可选 Slot | EraCharacterEquipmentStateDto |

目录接口不要求玩家档案已初始化，仍要求现有登录认证和有效 ERA 会话。两个角色接口实现 IRequireEraPlayer，复用玩家预加载，并通过 IEraCharacterContext 校验本人角色；路由 CharacterId 覆盖查询参数。禁用角色可以只读查看，响应明确携带 IsCharacterDisabled，不表示其可继续参与游戏或写操作。

目录响应包含 SchemaVersion、Version、Definitions、GenerationRules 和 InventoryCapacityPerSlot。生成规则包含版本、分配百分比、最大浮动及五档预算，不包含掉落概率或品阶颜色。

两个角色接口都返回完整已穿槽位及背包计数，装备接口也返回完整背包，因此客户端一次读取即可获得一致状态，不必合并两次查询。背包接口可使用数值 Slot 筛选对应分区候选，协议数值见基础实现说明；筛选不会改变其他分区计数或已穿数据。候选限定为该分区的未装备实例，并检查可用定义的兼容关系，最多 12 件；缺定义时按保存分区降级展示，不据此保证未来写操作一定允许装配。

快照主要字段：

| 字段 | 含义 |
| --- | --- |
| CharacterId / IsCharacterDisabled | 角色身份与禁用状态 |
| EquipmentVersion | 本次资产快照版本，独立于角色资料和各实例版本 |
| ManifestVersion | 本次使用的当前展示目录版本；目录不可用时为空 |
| FilterSlot | 当前候选筛选槽位，无筛选时为空 |
| TotalInventoryCount / TotalInventoryCapacity | 所有分区的背包实例总数与 72 件容量，筛选不改变计数 |
| InventoryPartitions | 六个分区的 Count 和 Capacity，已穿物品不计入 |
| InventoryItems | 当前背包或筛选结果，按 CreatedAt、Id 排序，名称相同也保留独立 ID |
| EquippedSlots | 全部六个槽位，空槽 Equipment 为 null |

资产版本、背包、已穿装备和护甲属性通过一条 LEFT JOIN 查询读取，避免跨语句混合资产状态。当前展示目录独立读取，以 ManifestVersion 明确其版本；其变化不重新生成资产、调整分区或修改 EquipmentVersion。客户端不得将不同 EquipmentVersion 的资产响应拼接使用。

历史六维只读取保存值，不按当前预算、浮动或生成规则版本重新校验，也不截断超过最终生效上限的贡献。缺失护甲属性、重复实例／槽位、错误归属或超容量等无效资产状态返回错误，不隐藏异常实例后伪装为空背包。

世界操作限制随后已接入同一 SQL 快照的 `EquippedOperationRestriction`，包含世界身份及世界／限制版本，无继续世界时为空；见 [世界实例与装备限制接口](世界实例与装备限制接口.md)。角色 EquipmentVersion、世界版本和限制版本须分别处理，历史装备回执不能覆盖较新的限制。位置与归属写入继续在统一玩家、角色锁范围内递增装备及实例版本。

## 错误与处理

沿用 EraResponse 包装及项目现有 HTTP／验证处理方式，下表的 Code 指业务响应状态。

| ErrorCode | Code | 处理 |
| --- | --- | --- |
| `era.equipment_config_unavailable` | 503 | 目录记录缺失、版本或载荷无效；目录接口不可当作空目录成功 |
| `era.equipment_data_unavailable` | 503 | 资产数据不完整或状态异常；保留旧展示并提示读取失败 |
| `era.equipment_invalid_slot` | 400 | 可解析但未定义的槽位协议值，修正后重试 |
| `era.character_not_found` | 404 | 角色不存在、不属于当前玩家或在两次归属读取间消失 |
| `era.unauthorized` / `era.player_not_found` | 401 / 404 | 沿用现有登录或玩家初始化处理 |

无法绑定的查询参数和空角色 ID 沿用现有模型／消息验证错误。数据库未应用迁移时不能保证上述业务错误包装，必须先通过正常发布流程准备结构；GET 不会补表。
