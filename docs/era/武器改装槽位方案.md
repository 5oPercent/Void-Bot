# 武器改装槽位方案

更新日期：2026-10-25。源码已接入；未编译后端或 Godot 项目，未执行数据库迁移及真实 HTTP／游戏验收。

## 配置与资产边界

采用整套方案复用：`WeaponTemplate.SlotConfigurationId` 引用一个 `WeaponSlotConfiguration`，模板不再内嵌 `Slots`。多个模板可共享方案，复制方案时不提供方案和槽位 ID，由后端在保存时生成，再关联需要独立扩展的模板。

- `SlotTypes`：`Id`、`Name`。可增删的适配类型字典，替代固定五项枚举。
- `SlotConfigurations`：`Id`、`Name`、`Note`、`Slots`。
- 方案槽位：`Id`、`Name`、`SlotTypeId`、`CandidateCount`、`DisplayOrder`、`Pool`。
- 池条目：`ModDefinitionId`、`Weight`；公共改装通过 `SlotTypeId` 指定适配类型。
- 实例槽位：`SlotId`、`Name`、`SlotTypeId`、`DisplayOrder`、`Candidates`、`SelectedCandidateId`。
- 玩家选择请求：以 `SlotId` UUID 替换旧 `Slot` 整数，其余请求 ID、三个版本和幂等语义沿用。

`SlotId` 代表具体槽位，`SlotTypeId` 仅用于匹配候选。同类型可以在方案中出现多次，例如主瞄具与副瞄具，二者独立选择并分别计算效果。同一改装在不同槽位同时选中时，各槽的修正各应用一次，沿用固定加值汇总后乘加算百分比的公式。

槽位数允许为零且可按需增加；配置集合与每方案槽位最多 10000 项，同时受完整目录 1 MiB 限制。每槽仍抽取 1～16 个不同候选，候选池最多 256 项，权重为正整数且总和不超过 Int32 上限。顺序为 `DisplayOrder`、槽位 UUID；名称、类型和排序不承担槽位身份。

名称必填且最多 128 字符，方案备注最多 2048 字符；槽位 ID 在整个目录中唯一。修改槽位类型需重新创建该槽且不发送 ID，由后端分配；改名／排序保留已有 ID。复制得到不含身份的草稿，后端保存后分配正式 ID。每个引用方案的模板（包括停用模板）都要检查投射物速度、蓄力时间等属性适用性。

方案调整和模板更换方案仅影响后续生成。已有实例保留生成时的槽位名称、类型、顺序、候选与已选项；待发固定奖励也使用既定快照，不读取新池重抽。模板基础属性和公共改装效果仍采用当前目录规则，本次不改变这部分策略。零槽武器使用空槽位列表，客户端禁用改装入口。

## 管理接口

前缀：`/api/era/admin/equipment`。沿用后台权限、全局装备目录版本、立即发布及现有分页响应。无游戏会话要求。

| 方法 | 路径 | 请求／返回 |
| --- | --- | --- |
| GET | `/weapon-slot-types` | `pageIndex`、`pageSize`、可选 `search`；分页类型 |
| GET | `/weapon-slot-types/{id}` | 类型详情 |
| POST | `/weapon-slot-types` | 新建 `{ expectedManifestVersion, slotType }`，不含 ID，由后端生成 |
| POST | `/weapon-slot-types/{id}` | `{ expectedManifestVersion, slotType }` |
| POST | `/weapon-slot-types/{id}/delete` | `{ expectedManifestVersion }` |
| GET | `/weapon-slot-configurations` | 同上分页及搜索；分页方案 |
| GET | `/weapon-slot-configurations/{id}` | 方案详情 |
| POST | `/weapon-slot-configurations` | 新建 `{ expectedManifestVersion, slotConfiguration }`，不含 ID，由后端生成 |
| POST | `/weapon-slot-configurations/{id}` | `{ expectedManifestVersion, slotConfiguration }` |
| POST | `/weapon-slot-configurations/{id}/delete` | `{ expectedManifestVersion }` |

单项保存返回 `{ version, savedId, configuration }`，`savedId` 是已保存对象的正式 ID；新建调用集合 POST，`/{id}` 只更新已有记录。其他写入继续返回 `{ version, configuration }`；`configuration` 必须完整包含 `templates`、`modifications`、`statMappings`、`slotTypes`、`slotConfigurations` 五个集合。列表／详情的 `version` 仍在响应顶层。公共改装列表按可选 `slotTypeId` 过滤，旧 `slot` 参数不再属于契约。

现有模板保存、目录清单、预检和整批发布均使用新结构。模板和新槽位的 ID 不由 Web 生成。模板内嵌 `slots`、整数 `slot` 不属于当前契约。单项配置可按类型 → 改装 → 方案 → 模板的依赖顺序保存；完整目录发布沿用统一校验及原子保存流程。Int64 目录版本的前端精度处理、未知结果核对和冲突保护保持不变。

方案删除保护所有模板引用；类型删除保护方案槽、公共改装、实例快照和待发奖励引用；公共改装删除或改类型保护已有候选。删除方案内的槽位不会删除对应的旧实例槽位。配置引用无效沿用 `era.weapon_invalid_configuration`，历史资产引用或身份类型冲突沿用 `era.weapon_reference_conflict`，版本冲突沿用原错误码。

Web 管理页的“改装槽位方案”独立提供添加、删除、上下移和复制；模板仅选择方案并只读预览。关联模板数从完整同版本目录计算，界面标明读取版本；复制后的方案仍需单独保存发布和关联模板。基础属性映射和 101／102／103 穿戴位置保持独立。

## 后端生成 ID 与连续新增

模板、属性映射、槽位类型、方案、改装项及方案内槽位的 DTO 均以 `Guid.NewGuid()` 初始化 `Id`。Web 新建或复制时不发送 ID，由 DTO 默认值生成；`Save` 命令直接使用 DTO 原有的 `Id`，更新接口将路由 ID 写入 DTO。显式空 Guid、空对象和空槽位等异常输入由 Validators 拒绝，控制器和服务不重置或补正。

保存沿用按 ID 新增或替换的流程，完整目录预检及发布继续执行配置与引用校验。保存响应包含 `savedId`，供 Web 定位保存项和继续新增。此调整不改变存储结构，无需新增迁移或提升缓存版本。

槽位类型新增默认按回车保存并继续新增，不重复弹确认；保存成功后使用响应版本打开无 ID 的新草稿并聚焦名称。仅保存会停留在后端返回的正式对象；失败或结果未知时保留输入，沿用并发与核对保护。
