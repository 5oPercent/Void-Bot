## HTTP 契约

全部路由位于 `/api/era/worlds`，沿用登录、`EraClientSession`、玩家预加载、Mediator 和统一业务错误处理。正文不能覆盖路由 `WorldInstanceId`。GET 不写数据库、不触发 Redis CAS、不自动修复房主记录。

| 方法与路由 | 消息 | 行为 |
| --- | --- | --- |
| POST `/api/era/worlds` | `RegisterEraWorldCommand` | 当前房主登记，分配 WorldInstanceId，初始 Building |
| GET `/api/era/worlds/current` | `GetCurrentEraWorldRequest` | 本人仍在继续的世界；没有则成功返回空 Data |
| GET `/api/era/worlds/{worldInstanceId}` | `GetEraWorldRequest` | 本世界成员读取当前持久状态，允许读取本人历史世界 |
| POST `/{worldInstanceId}/ready` | `ReadyEraWorldCommand` | 当前房主确认构建完成，转为 Ready |
| POST `/{worldInstanceId}/heartbeat` | `HeartbeatEraWorldCommand` | 本人仍在继续的成员报告存活，不改变房主与业务版本 |
| POST `/{worldInstanceId}/join` | `JoinEraWorldCommand` | 有效队员加入原世界，不创建新世界 |
| POST `/{worldInstanceId}/recover` | `RecoverEraWorldCommand` | 新房主完成队伍迁移后，恢复原世界的房主及代次 |
| POST `/{worldInstanceId}/equipment-restriction` | `SetEraWorldEquipmentRestrictionCommand` | 当前房主声明限制值 |
| POST `/{worldInstanceId}/leave` | `LeaveEraWorldCommand` | 只报告本人退出；最后一人退出才结束世界 |
| POST `/{worldInstanceId}/end` | `EndEraWorldCommand` | 当前房主明确结束，或以 ConstructionFailed 释放失败构建 |

登记正文包含 `TeamId`、`MemberId`、`RequestId`、`AuthorityEpoch` 和 `WorldDefinitionId`。定义标识只作恢复元数据，不证明地图配置合法或奖励真实发生。客户端不指定 WorldInstanceId、房主或成员名单作为可信结果；后端读取有效队伍成员并核对角色归属与禁用状态。

除心跳外，其余写操作包含路由世界标识、`MemberId`、`AuthorityEpoch`、`ExpectedWorldVersion`。心跳只含世界与成员标识。限制声明另含 `IsRestricted`；结束另含 `ConstructionFailed`，仅 Building 可声明构建失败。版本均为正数，枚举显式赋值。

登记成功返回 `EraResponse<EraWorldDto>`。同队同 RequestId、同登记参数返回原世界当前状态，不再分配身份，结束后也不能借原请求重新开局；改参数返回创建冲突。正常重开使用新 RequestId，先结束旧实例再登记新实例。

普通写操作按世界版本检查；Ready 已就绪、Recover 已恢复同一房主代次、Join 已是同一继续成员、Leave 已退出、End 已结束时，可返回当前状态而不再递增版本。它们是状态幂等操作，不保存不可变历史回执；与装备装配回执的语义不同。限制声明遇到过期世界版本会拒绝，即使期望的布尔值碰巧相同，也不能越过版本检查。

## 身份、状态与成员

WorldInstanceId 不等于 TeamId、地图定义、种子或房主代次。每队通过 `EraWorldTeamState.ActiveWorldId` 在协调锁内维护一个活动世界。登记和晚加入检查已有活动成员，数据库再以可空 ActivePlayerId、ActiveCharacterId 唯一索引保证每玩家、每角色只继续一个世界；成员和角色的复合归属外键沿用角色所有者约束。

World.Version 初始 1，生命周期、成员、权限恢复或限制发生变化时递增。RestrictionVersion 初始 0，仅限制值改变时递增；角色 EquipmentVersion 与实例 Version 保持各自原语义，限制声明不修改装备版本。

世界初始 Building，构建成功才 Ready。明确结束或最后一人离开进入 Ended；构建失败进入 BuildFailed。终态释放队伍活动指针和成员活动索引，保留世界及成员历史。重复操作旧终态世界不能清除新世界指针。

离开只处理经过当前账号认证的本人成员，不依赖 Redis 租约仍存在，便于断线后释放。其他成员继续时不结束世界；地图块、区域完成、复活和客户端释放场景不对应结束 API。已离开的同一世界成员不能静默重新加入或换角色；历史读取仍允许。客户端报告离开时还应通过既有队伍就绪能力撤销其 CanHost，避免已退出世界的成员继续成为迁移候补。

登记时加入全部当前有效队员；晚加入队员调用 Join。进入或恢复原世界时先读取既有队伍，再读取世界状态。房主迁移继续使用既有 `CompleteEraHostMigrationCommand` 完成 Redis 迁移，新房主随后调用 Recover，沿用世界 ID、成员和限制。若新房主此前尚未成为世界成员，先 Join 原世界再 Recover；Join 允许采用已完成迁移的新队伍代次，不要求 SQL 世界权限已恢复。

GET 返回的是最近成功登记／恢复的持久房主与代次，不把它当作实时授权凭证。迁移中的 Redis 状态或更高队伍代次不由 GET 自动写回，普通房主写入在恢复前拒绝。世界及成员查询在一条 SQL 内读取，避免版本与成员状态拼接。

## Redis 与 SQL 的一致性边界

队伍仍由 Redis CAS 管理，世界和装备由 MySQL 管理。没有新增第二套房主选举，也不把两种存储称为同一事务。

队伍实际 Redis 提交前，通过独立 MySQL 连接锁定 `era_world_team_state` 的队伍行；切队按队伍 ID 排序锁两行。CAS 回调内仍不执行 SQL 或网络副作用。发送 Redis 脚本后等待结果，协调事务只持久化锁行，释放后不再持有锁，不提交调用方资产。

每次持锁的队伍提交与世界权限写入还推进 Redis `era:world:{era-teams}:authority-fence:v1:{teamId}` 的 INCR 栅栏。提交脚本先核对令牌再执行原 CAS；切队同时核对两队。这样即使旧 Redis 请求超时后才在服务器执行，只要新的世界操作已经进入权限检查，旧令牌就失效；若旧提交先执行，新的操作会读取提交后的队伍。栅栏只递增，不过期或重置，晚到的 INCR 也只能使先前令牌失效。该新命名空间不改变现有队伍 JSON 或既有缓存版本。原有社交通知仍固定读取第 7／8 个时间与事件参数，不把新栅栏误用作通知元数据。

世界写操作在 Mediator 的 SQL 事务内先锁同一队伍协调行，再锁世界行，在锁内读取 Redis 的有效队伍、当前房主、成员及代次，直到世界事务提交／回滚才释放。这样迁移不能在一个已授权世界写操作尚未完成时越过它；迁移之后的旧房主请求会读到新代次并被拒绝。Redis 不可用时拒绝新增世界权限写入，不用 SQL 历史房主冒充实时授权。

队伍过期由租约决定，不能以 SQL 锁延长 Redis TTL。后续异常结束采用 [独立存活策略](世界存活与结束.md)，不直接以 Redis TTL 或一次读取失败结束世界。所有实际改变队伍／房主的路径，包括后台清理及切队，都经过同一提交协调；普通只读、打洞及通知查询不获取该 SQL 锁。部署前须应用 Script0031／Script0032，并让所有写队伍的后端实例使用此协调实现。

## 已穿装备限制

世界限制由当前房主声明，适用于该世界仍继续的角色。为真时禁止替换或卸下当前已穿装备；空槽装配允许。未来已穿直接丢出或转移必须复用此检查，背包操作不因该限制被禁。

装备写操作先锁玩家、角色，再对当前世界／成员执行共享锁读取，随后锁装备与护甲属性。限制声明和世界结束需要世界排他锁，须等待装备事务完成；限制先提交时，后续装备操作会读取新限制并拒绝受限操作。新成员插入还受角色归属外键及活动成员唯一约束保护。数据库死锁／连接失败仍按既有基础设施错误处理，整笔回滚后再读取状态重试，不包装为成功。

装备 GET 在原有单条快照 SQL 中一并读取 `EquippedOperationRestriction`：含 WorldInstanceId、WorldVersion、RestrictionVersion 和 IsRestricted；为空表示该角色当前没有仍在继续的世界。本字段不会因目录缺失而消失。

历史装备成功回执仍保存当时完整状态，限制后来变化也不重写旧回执。客户端必须按世界身份、WorldVersion／RestrictionVersion 独立处理限制信息，不能仅比较 EquipmentVersion 后用旧回执覆盖新限制；重连或不确定时重新查询。
