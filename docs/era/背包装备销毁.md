# 背包装备销毁

`POST /api/era/characters/{characterId}/inventory/destroy`：当前登录玩家批量销毁本人角色的背包装备，武器与护甲共用此接口。角色 ID 由路由覆盖。

请求示例：

```json
{
  "requestId": "d660aa02-28a2-44c3-aecb-0af33eca4780",
  "expectedEquipmentVersion": 3,
  "items": [
    {
      "equipmentInstanceId": "baaa57b1-6be7-487b-8268-5bb71711fae0",
      "expectedItemVersion": 5
    },
    {
      "equipmentInstanceId": "e504d22c-9bb4-43f2-9631-c704ac4af09d",
      "expectedItemVersion": 2
    }
  ]
}
```

- 一批 1～120 件，ID 不得为空或重复，每件实例版本必须大于 0。任一目标缺失、已穿、属于其他角色、版本不符或版本溢出，整批拒绝，不产生成功回执。
- 仅操作 `Inventory`。角色禁用后拒绝新操作；世界已穿装备限制不阻止背包销毁，不要求世界仍存在或当前模板可用。
- 沿用装备写事务、玩家及角色锁、实例条件更新和通知。整批成功仅增加一次角色 `EquipmentVersion`，各目标实例版本各增加一次。
- 实例位置变为 `Destroyed`，清空当前玩家、角色和已穿槽位；保留实例、护甲属性、武器候选／选择、奖励、分享、地面历史与原回执，不物理删除，不返还材料。
- 成功沿用 `EraEquipmentOperationResponse`，`data.operation = 6`（`Destroy`），`data.state` 为不含本批目标的完整角色装备快照。
- `RequestId` 与装配、卸下、拾取、丢出及改装共享玩家级唯一范围。同一成功请求的相同目标／版本可按任意顺序重试，返回原回执并标记 `isReplay = true`；参数或操作改变则返回 `era.equipment_idempotency_conflict`。历史回执不会恢复资产，也不能覆盖客户端较新快照。
- 参数、版本、归属和失败处理沿用 `era.equipment_*` 错误；SQL 中途条件更新冲突及回执保存失败必须由工作单元回滚整批。

复用既有位置字段、回执表及通知，不增加数据库迁移或修改缓存格式。

测试源码：`EraEquipmentOperationFixture` 覆盖批量成功、整批拒绝、幂等、角色权限、定义缺失、世界限制与写入异常；`EraIntegrationFixture.Destruction` 覆盖实际位置／归属变更、历史重放、中途 SQL 冲突及回执保存失败回滚。本轮只做静态检查，按约束未编译或运行这些测试，仍需真实 HTTP 与 Godot 联调。
