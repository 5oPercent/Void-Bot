# 护甲模板与改装

护甲模板、改装项、槽位类型、整套槽位方案分别保存为关系数据，发布版本与武器共用装备目录行。不存在旧护甲数据，使用 Script0041_init_era_armor_templates.sql 正常迁移；脚本不创建示例模板或装备，也不转换旧资产。目录契约为 SchemaVersion 2，移除旧 Definitions 展示定义，统一读取 Armors.Templates。

模板字段：后端生成的 Id、Name、Icon、Note、IsGenerationEnabled、CompatibleSlots、可空 SlotConfigurationId。未关联方案或关联空方案均为合法无槽位护甲。六维仍由既有品阶预算和随机生成器生成，模板不包含基础六维副本。

方案内槽位包含后端生成的 Id、Name、SlotTypeId、CandidateCount、DisplayOrder 和带 Weight 的去重候选池。同方案槽位类型不能重复，候选必须与类型一致；槽位数量按方案配置，不固化角色 UI。生成结果保存独立槽位名称、类型、顺序、固定候选与当前选择，后续修改方案不会改变已有实例。

保存与发布均保留共享目录版本锁，只更新有变化的记录；方案槽位／候选池及属性修正子记录只在对应内容变化时替换。名称、图标、停用和普通数值调整不扫描玩家资产或待发奖励。删除模板、删除／改类型的改装、缩减兼容部位等可能使已有引用失效的调整，按受影响编号查询资产；武器额外检查移除蓄力／投射物属性及新增相应修正的兼容性。待发计划仍为 JSON，仅在可能破坏引用时读取。护甲和武器共用改装选择流程及加权不重复抽样，接口字段与回执格式保持原样。

## 管理接口

沿用 EraAdminController 的 Security 权限管道，不在 service 判断管理员。以下路径前缀为 /api/era/admin/equipment/，集合支持分页 GET 和新建 POST，单项支持 GET、更新 POST、/{id}/delete POST：

- armor-templates（另有 /{id}/disable）。
- armor-modifications。
- armor-slot-configurations。
- armor-slot-types。

armor-configuration/validate 用于发布前预检，armor-configuration/publish 原子发布整份护甲目录。单项保存和完整发布均带 ExpectedManifestVersion，事务中锁定共享目录行。新建 Id 在 DTO 默认值生成；空 Id 和无效输入由 Validators 拒绝。Web 不创建或编辑正式编号。

受实例、奖励池或待发放计划引用的模板、类型和候选不能删除或改成不兼容关系；停用只禁止后续生成。跨护甲／武器模板的 Id 不得冲突。

## 实例操作与属性

护甲选择接口：POST /api/era/characters/{characterId}/equipment/{equipmentId}/armor-modifications/select。字段与武器选择一致：RequestId、SlotId、CandidateId 和目录／角色装备／实例预期版本；只接受实例原有候选。操作类别 SelectArmorModification = 7；复用玩家归属、角色与世界限制、幂等回执、原子版本推进及装备更新通知。

ArmorAttributes 保存首次随机生成原值，ArmorModifications 保存固定候选，ArmorEffectiveAttributes 返回当前改装效果。改装修正只针对强度、生存、机动、聚焦、效率、抗性，先累计固定加值再乘以 1 + 百分比累计，非负结果按远离零四舍五入为整数；不在单件护甲阶段限制为 100。角色与 BUFF 汇总后仍按既有战斗规则限定最终 0～100。切换候选不修改或重掷原值。

背包奖励、地面奖励、抽池、直接条目、拾取、丢出和销毁沿用现有装备流程，候选与六维在同一正式发放事务保存。无槽位护甲生成零候选，客户端显示禁用的“无法改装”，鼠标、键盘和手柄均不得进入改装页。武器采用同一无槽位交互规则。

本轮仅源码与静态检查；不编译项目、不执行数据库迁移或真实装备写入。
