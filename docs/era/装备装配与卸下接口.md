# 装备装配与卸下接口

更新日期：2026-10-21。

本批在 [装备存储与只读接口](装备存储与只读接口.md) 基础上接入本人角色装配、替换与卸下。整体进度见 [后端 TODO](角色装备与奖励后端TODO.md)。本文描述源码契约；尚未编译、执行测试、应用迁移或运行联调。

## 接口与输入

| 方法与路径 | 消息 | 用途 |
| --- | --- | --- |
| POST `/api/era/characters/{characterId}/equipment/equip` | EquipEraEquipmentCommand | 背包候选装入空槽，或原子替换目标槽位旧装备 |
| POST `/api/era/characters/{characterId}/equipment/unequip` | UnequipEraEquipmentCommand | 将指定已穿装备卸下到角色共用背包 |

沿用登录认证、ERA 客户端会话和 IRequireEraPlayer。Controller 用路由覆盖正文 CharacterId，再发送 Command；Service 通过 IEraCharacterContext 验证归属并先锁玩家、再锁角色。禁用角色不得发起新的资产变更，已有成功回执仍可查询式重试。

共有字段：

| 字段 | 要求 |
| --- | --- |
| RequestId | 非空 GUID，在当前玩家的装备写操作范围内唯一，覆盖不同角色及两类操作 |
| EquipmentInstanceId | 实际候选或需要卸下的实例 ID，不使用名称识别 |
| Slot | 目标已穿槽位，使用已确认的护甲协议数值 |
| ExpectedEquipmentVersion | 最近读取的角色装备快照版本，非负，不是角色资料 Version |
| ExpectedItemVersion | EquipmentInstanceId 对应实例的版本，必须大于 0 |

装配另需 ExpectedManifestVersion，取读取候选时的目录 Version；不能使用生成规则版本代替。ExpectedEquippedEquipmentInstanceId 和 ExpectedEquippedVersion 必须成对提供：空槽都为 null，替换时分别为目标旧装备的 ID 与版本。

以下仅演示空槽装配字段，ID、槽位和版本必须替换为真实查询结果：

```json
{
  "RequestId": "11111111-1111-4111-8111-111111111111",
  "EquipmentInstanceId": "22222222-2222-4222-8222-222222222222",
  "Slot": 1,
  "ExpectedEquipmentVersion": 3,
  "ExpectedItemVersion": 5,
  "ExpectedManifestVersion": 7,
  "ExpectedEquippedEquipmentInstanceId": null,
  "ExpectedEquippedVersion": null
}
```

卸下不要求目录版本：旧定义被移除或目录不可用时，仍可按实例当前位置、已穿槽位和版本卸下。未知物品、其他角色物品、地面或仓库物品不能通过这两个接口直接操作。

## 业务行为

装配只接受当前角色背包内的未装备实例，按当前有效定义检查目标兼容关系，不能把身上其他槽位的实例直接作为候选。缺少有效定义时允许查询降级展示，但不能据此装配。兼容多个槽位的实例依旧只占一个背包位置，候选资格取当前模板的 CompatibleSlots。

容量按最终状态检查，不按 SQL 中间步骤的临时数量检查：

- 空槽装配使角色背包总数减少 1 件。
- 等量替换先扣除候选，再将旧装备放回背包；共享总数已为 120 件时也可替换。
- 兼容规则允许替换时，旧装备直接回到同一个角色背包；所有类别共享总容量。
- 单独卸下使背包总数增加 1 件，已有 120 件则拒绝，保留原装备状态。

成功后受影响实例的 Version 各增加 1，角色 EquipmentVersion 只增加 1，不改变角色资料 Version。六维、品阶、首次生成时间、分享资格及实例身份不重新生成或刷新。

## 事务与防重

普通 Command 仍由现有工作单元开启并提交事务。本批命令声明 ReadCommitted；顺序为玩家行锁 → 角色行锁 → 回执读取 → 装配所需目录共享锁 → 按 ID 顺序锁装备 → 锁对应护甲数据。目录共享锁固定本次兼容规则，更新目录需等待操作完成。

装备实例用 AsNoTracking 当前锁定读取，成功结果先在独立快照中预建。版本、目标旧装备、完整属性及最终容量全部校验通过后，才开始数据库写入。替换时先将旧装备改回背包并清空 EquippedSlot，再将候选穿上，避免同槽唯一索引的临时冲突。

位置更新带上玩家、角色、原位置、原槽位和预期版本条件，每条必须恰好影响一行。若后续 UPDATE 失败，必须抛出异常让外层工作单元回滚，不能返回普通失败响应后提交第一条 UPDATE。Service／DataProvider 不自行 SaveChanges 或 Commit；根角色版本及成功回执随外层工作单元一起保存。取消、回执保存失败及最终提交失败也应走同一异常回滚路径。

新增 `Script0030_add_era_equipment_operation_receipts.sql`，不修改已有迁移。回执表以 PlayerId + RequestId 唯一，保存操作、角色、规范化请求参数和固定成功结果，关联角色使用限制删除。回执参数快照当前 SchemaVersion 为 1，覆盖操作类型、角色、实例、槽位及全部预期版本；同一 RequestId 的重试必须比较完整请求参数。

同一成功 RequestId 的相同参数返回原结果，IsReplay 为 true；更改角色、操作、目标或预期版本会返回幂等冲突。只对成功操作保存回执，写入前失败不产生成功回执。超时且不能确定是否成功时，必须先以原参数重试，不能换请求 ID 重做操作。

## 成功响应与历史状态

沿用 EraResponse，Data 为 EraEquipmentOperationReceiptDto，包含 RequestId、CharacterId、Operation、PreviousEquipmentVersion 及完整 State。State 与只读接口共用快照结构，包含更新后的实例、槽位、背包总数与容量及版本。

回执中的 State 固定为当时成功状态。装备以后再次换装、卸下或转移后，旧请求重试仍返回旧状态，不恢复资产，也不新建装备。客户端必须同时处理 IsReplay 与 EquipmentVersion：不能用较旧回执覆盖已应用的新版本，不确定时重新读取当前快照。

## 错误处理

下列 Code 指项目统一包装中的业务状态；无法绑定及基本消息验证错误沿用项目既有处理。

| ErrorCode | Code | 含义 |
| --- | --- | --- |
| `era.equipment_invalid_operation` | 400 | 未定义槽位、原槽位成对参数或其他业务输入无效 |
| `era.equipment_character_disabled` | 403 | 角色已禁用，不能新增写操作 |
| `era.equipment_operations_restricted` | 403 | 当前世界限制操作已穿装备，拒绝替换和卸下，空槽装配仍允许 |
| `era.equipment_not_found` | 404 | 实例不在当前本人角色背包及已穿快照内 |
| `era.equipment_version_conflict` | 409 | 角色装备版本、实例、目标槽位或条件更新已变化 |
| `era.equipment_config_version_conflict` | 409 | 目录版本变化，应刷新后重新选择 |
| `era.equipment_definition_unavailable` | 409 | 实例对应的当前定义缺失，无法装配 |
| `era.equipment_incompatible_slot` | 400 | 当前定义不兼容目标槽位 |
| `era.equipment_inventory_full` | 409 | 旧装备回包后背包总数将超过 120 件 |
| `era.equipment_idempotency_conflict` | 409 | 成功请求 ID 被用于其他参数或其他操作 |
| `era.equipment_config_unavailable` / `era.equipment_data_unavailable` | 503 | 必需目录、资产、版本或已有回执异常，不能伪装成功 |

角色不属于当前玩家仍使用 `era.character_not_found`；登录、玩家初始化和客户端会话错误沿用已有契约。数据库死锁、连接故障等基础设施失败不承诺转换成上述版本冲突，结果不明时按原 RequestId 查询式重试。
